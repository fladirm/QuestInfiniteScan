```text
  signed logical SigmaCarrierPageCoordinate -> PageRecord

PageRecord
  exact coordinate
  page/state/gauge/certificate generations and revision
  PageBlobHash
  conservative query-support-summary hash/receipt

  -> exact canonical SigmaCarrierCodec.EncodePage bytes
```

The first schema reuses the frozen `64x64`/`8x8` `EncodePage` stream rather than
inventing another page ontology. SHA-256 is a content/integrity locator only. A
lookup hit must validate complete object bytes, coordinate, generation, schema and
all fingerprints. Hash equality may not choose canonical order, D4 image, page
identity or physical state. An impossible collision or mismatching existing blob
fails closed rather than aliases content.

`EncodeSnapshot` remains an exhaustive oracle/import/export helper. Live commit
must never encode or sort every page. One changed page writes one immutable blob
and only the affected COW map path plus one new RootObject.

#### N5R-B — dirty-only durable transaction

For one selected immutable GPU revision:

```text
1. pin PublishedRevisionRoot, its exact dirty pages and certificate/frontier data
2. GPU encode/stage only touched pages using the existing exact codec; transfer
   completion asynchronously, never with synchronous readback
3. compare staged CPU/GPU bytes to canonical EncodePage/DecodePage or its proved
   direct equivalent
4. hash and write missing immutable blobs to same-filesystem temporary objects
5. flush blob contents and atomically install object names
6. COW-update only changed page-map and conservative-summary paths
7. write + flush the immutable RootObject
8. atomically replace + directory-flush HEAD LAST
9. mark exactly the reached page/certificate generations durable
```

Before step 8, the previous `HEAD` is authoritative and newly written objects are
unreachable garbage. After step 8, the complete new root is authoritative. Startup
walks only from `HEAD`, verifies reached objects and may reclaim unreachable
objects after all pinned durable roots/exports release. Android atomic-rename and
directory-durability behaviour must be device-tested; the existing journal
`WriteAtomic` helper is a donor, not unverified proof.

The GPU `PublishedRevisionRoot` and durable `HEAD` are distinct root selectors
linked by the exact revision stored in RootObject. A GPU revision may be newer but
is not called durable. Its dirty pages, minimal certificates and any unresolved
source evidence remain leased until HEAD reaches an equivalent generation. A
bounded persistence queue applies backpressure to new scan admission rather than
overwriting, dropping or accumulating unbounded revision resources. XR continues
to read its pinned immutable GPU root.

#### N5R-C — one disposable residency index

Implement exactly one sparse GPU lookup domain:

```text
(logical page coordinate, generation/root context)
    -> transient (segment/bank, physical slot, resident generation/state)
```

The reverse direction is one dense `ResidentSlotTable[slot]`. Do not copy a donor
second hashmap unless a separately measured lookup is actually sparse. Every
probe compares the full logical key; collisions are execution details.

State machine:

```text
ABSENT_IN_ROOT
COLD_DURABLE
LOADING
HOT_CLEAN
HOT_DIRTY
EVICTING
QUARANTINED
```

Only `ABSENT_IN_ROOT` uses the proved unbacked-`ZEmpty` theorem.
`COLD_DURABLE` exists physically in the pinned canonical root and can never be
treated as empty/no-support. Hash bucket, probe order, segment/bank/slot, allocator
order, resident generation and eviction order are noncanonical.

One or more fixed-size resident segments remain Vulkan binding banks. Segment
growth changes capacity only; it is not a page directory, world extent or
persistence unit. At fixed query-visible work, `1/2/7` resident segments leave the
hot graph and canonical bytes identical.

#### N5R-D — rehydrate, eviction and lifetime

Rehydrate:

```text
pin HEAD/RootObject/PageRecord generation
reserve an unpublished shadow slot
async-read and verify PageBlob
decode exact state + chi/kappa + certificate bytes
validate generation/fingerprints/support summary
wait for load/write completion
publish transient locator last
```

A load for a root that has since advanced may remain a clean cache entry, but it
cannot satisfy the newer query without an exact generation match. Missing,
stale or corrupt query-support summary causes conservative inclusion and load;
never omission.

Eviction is legal only when the page is `HOT_CLEAN`, the exact generation and its
support summary are reachable from durable `HEAD`, no selected root/readout/
persistence lease references it, and the last GPU reader/writer has completed.
Dirty pages first pass N5R-B. The old locator remains visible until the cold
transition is committed; no transient hole is allowed.

The non-negotiable resource-retirement gate is:

```text
durable replacement/root reachable
AND last GPU reader/writer completion proved
AND no publication/readout/persistence lease references the generation
    -> physical slot/resource may be reused or released
```

CPU reference count zero alone is insufficient. `Pending` retains both source and
replacement. Completion polling failure quarantines them. Never interpret a
failed fence as completion and never use `AsyncQueueSynchronisation/.passed` as a
graphics-queue migration proof. Reuse the current scanner-owned
`CPUSynchronisation` ticket recorded after all relevant commands or a four-byte
asynchronous readback token when durable staging itself needs one. Teardown and
clear follow the same rule.

#### N5R-E — convert the N4 capacity stop into cold continuation

N4 intentionally fails closed when:

```text
page-plan scratch capacity > legal resident current/shadow pair count
or the next canonical logical target has no resident pair
```

It zeroes mutation/clone/scatter indirect work and retains the prior root. N5 must
turn that exact receipt into bounded `COLD_DURABLE` eviction/rehydration or fresh-
page allocation work, retain the admitted observation/certificate, then replay the
same NativeCloseCommit against a compatible latest root. It may not produce
physical `UNRESOLVED`, `ZEmpty`, a permanent frame fault, a retry storm or an
out-of-range physical slot. If every slot is dirty, leased or awaiting GPU
completion, scan admission backpressures while immutable-root readout continues.

#### Query support and clear/restart

Every PageRecord carries or references the generated zero-false-negative
query-support summary; immutable map nodes may aggregate it conservatively.
Missing/stale/corrupt summaries mean possible contribution and cause rehydrate.
They never hide a page.

Stop/sleep flushes or preserves the current durable `HEAD` and never clears it.
Restart reconstructs the disposable locator/cache from `HEAD` and must reproduce
the same pages, certificates and readouts. Explicit clear first atomically selects
an empty durable namespace, then retires old resident/staging resources only after
the lifetime gate. It does not delete memory still referenced by GPU work.

Order:

```text
N5R-A object/codec CPU oracle
    -> N5R-B crash-safe dirty COW store
    -> N5R-C exact GPU locator + dense reverse table
    -> N5R-D asynchronous load/evict + completion/lease retirement
    -> N5R-E capacity-fault replay, clear/restart and device scale corpus
```

This is one N5 run and one semantic backing cut, not five runtime managers. Keep
hot `NativeCloseCommit` fixed; fixed cold encode/rehydrate work may use compact
worklists and indirect grids. No dispatch per page/segment, host page loop,
synchronous GPU readback or full-world traversal.

Hard-delete during cutover:

```text

physical slot/segment as page identity or root meaning
any second sparse reverse hash without a proven consumer
CPU-ownership-only Release/Dispose/recycle path
any cache-miss -> ZEmpty/no-support fallback
any per-page host dispatch/readback loop
any retry/watchdog path that drops the admitted observation
```

## 10. Stop rules

Stop the active run rather than broaden it if:

- the authoritative TOE artifact is missing or incomplete;
- `ZEmpty` representation parity or all-default quiescence cannot be proven;
- the exact `chi/kappa` map/reconstruction/transport/canonical-normalization theorem is missing or depends
  on observation/allocation order;
- state and gauge cannot be published under one atomic root;
- E22 contextual separation/complete-law sufficiency is assumed rather than
  proven/direct-S16 retained;
- a transparent mode is frozen without complete-program decoupling proof;
- a branch/scratch record acquires physical identity;
- a chart/surface/topology manager appears;
- a second modality-specific solver appears;
- old and replacement graphs both remain live;
- N3 cannot scan a fresh all-`ZEmpty` world without a legacy proposal path;
- the sole generator can still emit Candidate/Pending/Continuation/Novel/
  DirtyEdge ABI after N3;
- query-support culling lacks a zero-false-negative proof for nonresident/refined
  regions;
- the photometric nuisance law is replaced by an uncalibrated quality scalar;
- durable encoded backing/rehydration is postponed while final acceptance still
  claims an unbounded logical carrier;
- converged duplicate revisits retain proof/raw bytes linearly without an exact
  unresolved-information reason;
- any staged dispatch budget or final entry-point limit fails even if timing
  passes;
- an ordinary warm graph reaches `D_budget >= 100`, scales its graph-command sequence
  with page/segment/world/history size or hides permanent work as cold;
- dispatch reduction is faked by a serial generic interpreter;
- a run becomes production-LOC positive without an immediate deletion path;
- device failure would require changing native law outside the active cut.
