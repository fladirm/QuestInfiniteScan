# S4-08.2 — Exact GPU lowering and completion rebase

Status: planned/reopened; no runtime source has been changed for this run yet.

Canonical authority: `new_spec.md` / `CPQ4-2026-08-22-S16-v6`.

Reference points:

- control head: `c4220a36837fdfbbb0990cfeb00a375d548c7b26`
- executable-source reference: `6b3003a199df`
- installed device audit: first inverse submission stalls permanently after an
  unsupported `AsyncQueueSynchronisation` fence is polled

This run is an execution-lowering rewrite. It may not change the physical ontology,
the Q16.48 NumericDomain, source-cell semantics, first-hit causality, certificate
semantics, intrinsic topology, gauge meaning or the fact that `Psi` is the only
canonical world.

## 1. Why S4-08 is reopened

The installed Release proves that the current source is not device-closed:

```text
Create AsyncQueueSynchronisation fence
    -> submit first inverse transaction
    -> Quest reports async compute unsupported
    -> GraphicsFence.passed throws in LateUpdate
    -> _inFlight is never retired
    -> every later prediction is dropped
```

The captured log contains 1,703 identical fence exceptions in 28 seconds. Capture
continues to produce coherent frames, so this is a reconstruction-completion
deadlock rather than missing RGB/depth ingress. The same unsupported fence type is
also used by the capture and prediction rings, where an exception is currently
treated as “already passed”; that avoids the visible exception but permits unsafe
early resource reuse.

The performance audit additionally proves that the exact hot path is primarily a
scalar/reference implementation transcribed into HLSL:

- 16-limb schoolbook/carry loops for one 64x64 wide multiply;
- a serial 128-bit bit-at-a-time Q48 divider;
- 256-add Hadamard transforms instead of a 4-stage exact FWHT;
- lane-zero serial reducers in pose and proof;
- one thread owning complete 16D page/sample state in inverse commit;
- repeated RGB coefficient construction and excessive barriers;
- full-arena raw-slot scans;
- single-thread transaction/proof transforms;
- repeated ad-hoc workgroup scans.

These are rejected as the final Quest lowering even where their current output is
semantically correct.

## 2. Frozen semantic contract

Every replacement must obey all of the following:

1. Canonical results remain checked nearest-even/outward-rounded Q16.48.
2. Independent `RGB_L/R`, `DEPTH_L/R` and temporal cells meet only by exact
   componentwise intersection.
3. FP may schedule/visualize but never decide canonical mutation.
4. Signed-XOR, explicit bracketing, annihilator and associator semantics do not
   change.
5. Source order, lane order, subgroup width and dispatch decomposition do not
   change page or certificate bytes.
6. Page/block/buffer layout remains storage/execution only.
7. No readback scheduler, CPU pixel loop, CPU mesh or second world is introduced.
8. Runtime v1 hot-path implementations are removed after parity; there is no
   permanent runtime fallback/switch between old and new algorithms.
9. The CPU semantic oracle and generated scalar fixture evaluator remain tests,
   not a live reconstruction path.
10. A failed capability/parity/overflow gate fails closed before mutation.

## 3. Whole-file shader and binding rewrite protocol

Every shader/include touched by S4-08.2 is replaced as one coherent whole-file
implementation after its complete source/include/ABI/call-site review. It is not
incrementally patched. The old file may be consulted as a semantic/reference audit,
but its procedural structure is not copied forward.

Initial mandatory whole-file rewrite set:

```text
Sedenion16.hlsl
SigmaOperatorPlan.hlsl
SigmaPoseConsume.hlsl
SigmaPoseGauge.compute
SigmaRgbInverseMath.hlsl
SigmaRgbSourceCells.compute
SigmaInverseMath.hlsl
SigmaInverse.compute
SigmaConstraintPrior.hlsl
SigmaConstraintLedger.compute
SigmaInverseWorkAbi.hlsl
SigmaInverseWorkGraph.compute
SigmaGaugeRefinement.compute
SigmaTopologyMath.hlsl
SigmaIntrinsicTopology.compute
SigmaOperatorFixture.compute
```

Any additional shader/include that must change joins this same full-rewrite rule.
Trivial representation-neutral capture/copy kernels outside the changed dependency
graph remain untouched rather than being churned for appearance.

For each rewritten shader family, the same phase also replaces its C# execution
contract:

1. Define one authoritative kernel manifest containing kernel name, threadgroup
   shape, direct/indirect axes, required buffers/textures/constants, access mode and
   publication outputs.
2. Generate or centralize typed property IDs and bind methods from that manifest.
   Every dispatch binds its complete per-kernel resource set; no kernel depends on
   state left behind by a previous kernel binding.
3. Rewrite the owning C# recorder/controller to the new dispatch graph in the same
   change. Delete obsolete kernel indices, buffers, property IDs, dispatches and
   lifecycle branches immediately.
4. Keep command construction, work compaction, proof, commit, topology and
   completion GPU-resident. C# may own resources/fences/metadata only.
5. No `AsyncGPUReadback`, `GetData`, synchronous wait, callback decision scheduler,
   CPU pixel loop or CPU canonical decision is permitted.
6. No compatibility branch, old-vs-new runtime selector, catch-as-success path or
   legacy shader remains. Unsupported capabilities fail closed at initialization.
7. Preserve existing Unity asset GUIDs where a file path remains authoritative;
   every genuinely new Unity asset receives its `.meta` file.

Whole-file replacement gate for every phase:

```text
old shader body removed
new shader has one explicit ownership model
C# binder/dispatcher matches only the new kernels
all required resources are bound per kernel
no orphan kernel/property/buffer/call site remains
no CPU readback/fallback/legacy execution path appears
canonical fixture bytes match the semantic oracle
```

## 4. Deterministic implementation order

The phases below are executed in order. A later phase does not start until the
previous phase has its stated bit/capability gate. Each phase leaves the repository
compilable. No threshold tuning or S4-09 work is mixed into this run.

### Phase A — Completion primitive and lease lifetime closure (P0)

Affected ownership:

```text
Runtime/SigmaPrism/SigmaInverseController.cs
Runtime/SigmaPrism/Capture/GpuTextureRing.cs
Runtime/SigmaPrism/SigmaPredictionFrame.cs
new small shared completion helper under Runtime/SigmaPrism
```

Rewrite the three independent fence implementations into one queue-aware completion
ticket:

1. At initialization, establish the exact supported graphics-queue completion
   capability. The current live graph is submitted with
   `Graphics.ExecuteCommandBuffer`, not an async-compute queue.
2. Use a CPU-pollable graphics-queue fence for that path. Never create or poll an
   `AsyncQueueSynchronisation` fence when `supportsAsyncCompute == false`.
3. Reject startup/submission before retaining leases if no safe nonblocking
   completion primitive exists.
4. Polling failure latches one explicit scanner error and stops new inverse
   submissions. It must not throw every frame, claim completion or recycle a slot.
5. A ring slot is reusable only after its completion ticket proves completion.
   Remove both catch-and-return-true paths.
6. `_inFlight` retirement releases raw and corrected prediction leases exactly
   once after completion. Stop marks the transaction discard-only; it does not
   fake completion.
7. Sensor ingress remains nonblocking: when no completed ring slot exists, drop or
   defer reconstruction work rather than waiting or overwriting an in-flight slot.

Gate A:

- a platform fixture with async compute disabled never creates/polls an async-queue
  fence;
- a pending ticket cannot recycle capture/prediction storage;
- a completed ticket retires one submission exactly once;
- a forced polling error becomes one fail-closed state, not a frame exception loop;
- device log has zero `GraphicsFence.get_passed` exceptions and submitted/committed
  inverse revisions continue increasing.

### Phase B — `ExactALU-v2` packed-32 lowering

Primary files:

```text
Runtime/Resources/SigmaPrism/Sedenion16.hlsl
generated exact-ALU descriptors/helpers
CPU/GPU NumericDomain fixtures
```

#### B1. Wide multiply

Replace `SigmaU64MultiplyWide()` with a fixed four-product packed-32 circuit:

```text
a = a0 + 2^32 a1
b = b0 + 2^32 b1
p00, p01, p10, p11 = four exact 32x32 -> 64 products
fixed carry network -> exact 128-bit magnitude
```

The Vulkan lowering must use the proven extended unsigned multiply instruction or
an exactly equivalent fixed instruction sequence. No 16-bit limb arrays, nested
loops or data-dependent carry loops remain in the live helper. Signed Q48 multiply
then performs one sign transform, exact `>>48` quotient/remainder extraction,
nearest-even rounding and checked range validation.

#### B2. Exact division

Replace the 128-iteration bit divider with a normalized fixed-limb
`112-bit numerator / 64-bit denominator` quotient-and-remainder circuit specialized
for Q16.48:

```text
numerator = abs(a) << 48
normalize denominator by leading-zero count
estimate/correct a bounded number of 32-bit quotient limbs
produce exact quotient and remainder
apply sign and one shared rounding decision
```

`nearest`, `lower` and `upper` variants share this quotient/remainder core. The
outward result is chosen from sign, exact remainder and requested direction; the
core division is not repeated merely to obtain both interval endpoints. Divide by
zero, quotient overflow and signed minimum-magnitude cases remain checked failures.

#### B3. Fast exact cases

Generated descriptors route sign, XOR permutation, dyadic shift, comparison,
min/max and signed-dyad actions around generic multiplication/division. Constant
power-of-two division becomes an exact checked shift with the required rounding.

Gate B:

- exhaustive boundary classes plus deterministic random/adversarial vectors match
  the CPU widened oracle bit-for-bit for `qmul`, `qdiv`, `qdiv_lo`, `qdiv_hi`;
- overflow/zero/negative/tie-to-even cases match exactly;
- compiled Vulkan lowering contains no live 16-limb schoolbook loop and no
  128-step bit-division loop;
- the old live GPU implementations are deleted after parity;
- Quest microfixtures report operation counts and elapsed GPU time for old fixture
  reference versus v2 before the reference shader is removed.

### Phase C — `OperatorPlan-v2` fixed circuits

Primary files:

```text
Tools/sigma/generate_sigma_operators.py
Runtime/Resources/SigmaPrism/SigmaOperatorPlan.hlsl
shared generated reduction/scan/sort include(s)
```

Implement generated circuits rather than handwritten repeated loops:

1. `B` and `B^T`: one 16-lane, four-stage Walsh-Hadamard butterfly. Use widened
   exact intermediates with one checked final narrowing so the result equals the
   mathematical signed-accumulation oracle. Total work is 64 add/sub operations,
   not 256.
2. Six-component pose meet: generated signed min/max/valid tree.
3. Eight-certificate ordering: fixed stable sorting network with original source
   ordinal as the final tie-breaker.
4. Exact reductions: fixed trees for min, max, OR, AND, L1 and validity. Any sum
   whose reassociation could alter checked overflow uses widened intermediates and
   a fixed generated schedule.
5. Stable compaction: one reusable primitive with a capability-proven subgroup
   path and deterministic two-level shared-memory fallback. Both emit identical
   stable indices. Subgroup width is never semantic authority.
6. Generate one operator-cost record per plan (`signedAddSub`, `maskSelect`,
   `qmul`, `qdiv`, bytes) for section 44 counters.

Gate C:

- every generated circuit matches its scalar semantic reference bit-for-bit;
- stable scan/sort output is identical for all predicate/tie fixtures and supported
  subgroup widths;
- generated fingerprints are unchanged when semantics are unchanged, or the
  generator proves exact descriptor equivalence before an execution-plan
  fingerprint update;
- no handwritten duplicate 256-wide scan remains in a rewritten hot path.

### Phase D — Pose and RGB inverse kernel rewrite

#### D1. `SigmaPoseGauge.compute`

Keep the accepted exact point-to-plane, covariance-envelope, six-axis observability
and same-frame reraster semantics. Rewrite only execution layout:

1. Compute `maxIncrement[6]`, per-component contribution and total nuisance width
   once per source sample.
2. Derive each component width as
   `residualWidth + totalContribution - contribution[c]`.
3. Use coefficient sign to choose the two necessary outward divisions per
   component. Eliminate the four-division min/max formulation.
4. Map 64 source samples across 64 lanes. Reduce six interval components with the
   generated exact tree; lane zero publishes metadata only.
5. Apply the same cooperative tree to `ReducePoseGauge`; remove both 64x6
   lane-zero serial scans.
6. Keep `BuildCorrectedCalibration` as exact GPU consumption and preserve the
   accepted rigid SE(3) reraster contract.

#### D2. `SigmaRgbSourceCells.compute`

1. One 16-lane group continues to own one source cell, one lane per projective
   coordinate.
2. Build the invariant `7 constraints x 16 coordinates` coefficient table once
   per view direction/source cell and reuse it for all four canonical sweeps.
3. Preserve exactly `2 forward + 2 reverse` inequality order.
4. Replace repeated source-lane loops and validity barriers with generated 16-lane
   fixed reductions. The portable fallback and subgroup lowering must produce the
   same outward box.
5. Do not materialize a second RGB state or change the joint meet.

Gate D:

- oblique/grazing/dual-eye pose fixtures reproduce the exact accepted twist and
  corrected calibration bytes;
- pose source permutation produces the same twist cell;
- RGB cells match the scalar four-sweep oracle for every fixture exactly;
- no lane-zero 64x6 reducer, repeated pose nuisance calculation or repeated RGB
  coefficient construction remains;
- stage counters show 12 rather than 24 pose interval divisions per accepted
  six-component sample before zero-coefficient skips.

### Phase E — Inverse, proof and raw-lifetime kernel rewrite

#### E1. `SigmaInverse.compute::SolveAndCommitPage`

Use a coordinate-major 16D layout:

```text
256-thread group
    16 carrier samples x 16 S16 coordinates
four deterministic sample batches cover one 64-sample block/page unit
```

Each lane owns one operator coordinate. Small per-sample masks, keys and publication
facts use bounded shared storage. Prior/source meets, conflict gaps, width
reductions, FWHT inversion and candidate checks execute 16-wide. No thread owns
complete copies of all state/source/bounds arrays. The kernel writes scratch only;
the existing proof-gated immutable publication remains a later transaction stage.

#### E2. `SigmaConstraintLedger.compute::ReduceProofPage`

Replace the one-thread reducer with one 64-lane cooperative group:

```text
A  classify/compact 64 source samples stably
B  sort <=8 candidates with the generated stable network
C  coalesce equal provenance by exact intersection
D  run the canonical reverse-lexicographic redundancy sequence;
   16 coordinate lanes recompute each candidate meet cooperatively
E  write certificate bounds in parallel
F  lane zero publishes only counts/offsets/role metadata
```

The redundancy decision order remains exactly section 30.2. Only its 16-coordinate
meet is parallelized; candidates are not removed concurrently.

#### E3. Raw provenance allocation

Replace repeated full-arena flag scans with a segmented deterministic occupancy
bitmap:

```text
one bit per reusable live raw slot
word popcount + stable prefix
rank/select lowest free slots in source order
```

Pool lifetime depends on unresolved live evidence, never total submitted frames.
Segments grow/stage under the memory governor; there is no 4,096-frame or week-long
session ceiling. Pool pressure may defer/drop unresolved reconstruction work but may
not block sensor ingress or overwrite live provenance.

#### E4. Transaction commit

Rewrite `CommitInverseTransactions` as 64 lanes, one lane per block. Lane zero
publishes transaction metadata only after all block validity facts are reduced.
Rollback/retire is parallel and generation-safe; no single thread loops over all
64 blocks.

Gate E:

- exact committed carrier page, conflict and certificate bytes equal the scalar
  oracle for the same captured/synthetic inputs;
- source-order and L/R-order permutations remain byte-identical;
- certificate minimization order/result remains section 30.2 exact;
- register/local-memory inspection shows no per-thread full 16D source/state
  arrays in `SolveAndCommitPage`;
- raw allocation remains stable-lowest-slot and reusable across a simulated
  multi-million-frame session without monotonic exhaustion;
- no `numthreads(1,1,1)` full-page proof/commit kernel remains.

### Phase F — Gauge and intrinsic-topology lowering rewrite

#### F1. Gauge demand/proof

1. Map gauge-demand work coordinate-major: 16 coordinate workers cooperate on one
   spatial sample/triple and process the 64-sample block in fixed batches.
2. Evaluate the Hadamard/operator plan through the shared FWHT circuit.
3. Stage neighbour evidence once per batch; remove the 16 serial coordinate rounds
   and their repeated barriers.
4. Rewrite `TransformGaugeProof` cooperatively: coordinate lanes transform bounds,
   sample lanes transform masks/footprints, lane zero publishes metadata only.
5. Preserve the accepted bijective gauge map and byte-identical inverse roundtrip.

#### F2. Intrinsic topology

1. Replace `MarkTopologyCandidates`' handwritten Hillis-Steele scan with the shared
   stable compaction primitive.
2. Preserve the complete 168-action annihilator scan and lexicographic first argmin.
   Map 168 witness actions to active lanes and use remaining lanes only in the
   generated reduction; do not route signed-dyad action through generic qmul/qdiv.
3. Keep associator evaluation candidate-driven and only after the near-annihilator
   premise. Use generated exact reductions and the generation-keyed transition
   cache.
4. Keep the bounded fair candidate cap. Overflow remains pending work for a later
   frame, never silently discarded evidence.
5. Remove duplicate local scan/reduction implementations from topology kernels.

Gate F:

- gauge transform/inverse restores carrier/proof/topology bytes exactly;
- topology classes, annihilator IDs/errors and associator decisions equal the
  scalar reference for all H0 fixtures and candidate-order permutations;
- no image/XYZ identity, boundary object or alternate topology graph appears;
- topology dispatch remains active/dirty/candidate-local and bounded.
