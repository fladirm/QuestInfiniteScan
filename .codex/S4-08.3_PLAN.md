# S4-08.3 — Bounded streaming exact transactions

Status: frozen implementation plan; implementation in progress.

Canonical authority: `new_spec.md` / `CPQ4-2026-08-22-S16-v6`.

Implementation baseline: `8087a6ef1688af760642bb953eb2f2dd51509610`.

This run closes the live Quest device finding without changing the Sigma-PRISM-16
ontology. The only durable physical world remains:

```text
Psi : Sigma_2 -> S16
```

The defect is execution shape: the current live controller treats one complete
page transaction as one graphics-queue submission. Up to eight 64x64 gauge pages
can therefore expand to 32,768 exact stereo samples plus proof and topology in one
submission. Device evidence shows sustained 12--15 FPS while observing the scan,
approximately 96 ms GPU frames, application frames above 200 ms, fence timeouts
and downstream camera/depth starvation. The scan also produces no visible
committed carrier readout during that run.

The frozen correction is:

```text
canonical transaction != proof block != execution quantum
```

A canonical transaction remains proof-closed and atomically published. GPU work
needed to finish it is resumable across XR frames in bounded deterministic quanta.

## 1. Verified baseline facts

The following are source-audited facts at `8087a6e` and must not be rediscovered or
redesigned during implementation:

1. `SolveAndCommitPage` is already coordinate-major: one 256-thread group owns
   sixteen samples with sixteen S16 coordinate lanes per sample. S4-08.3 preserves
   that lowering and only gives it a bounded sample range/progress cursor.
2. One logical page contains 64x64 samples. Minimal proof storage is organized as
   sixty-four 8x8 blocks, each containing 64 samples and at most four persisted
   minimal certificates.
3. `PromoteGaugePage` already constructs exact left/right depth world cells,
   evaluates first-hit state and performs `SigmaLiftNullDepthMeet`. S4-08.3 does
   not add a duplicate preflight or a second bootstrap ontology. It decomposes this
   work into bounded blocks, adds mixed-eye association and makes exact outcomes
   explicit.
4. The current `GpuSubmission` retains raw and corrected prediction leases until
   the complete inverse graph finishes. A prediction lease retains its
   `StereoRigFrameLease`. A transaction lasting multiple XR frames therefore must
   not retain either lease.
5. Current novel promotion requires both `leftNovel` and `rightNovel`; mixed
   prediction cases are not resolved by exact carrier compatibility.
6. Generated operator costs include exact operator counts, but current Section 44
   byte estimates are heuristic constants. No exact per-kernel execution manifest
   exists.
7. Current publication toggles per-page `_CurrentFlags`; there is no generation-
   safe multi-page visibility manifest.
8. Current intrinsic topology executes after proof/commit and writes a disposable
   transition cache. That cache is not canonical authority and may never decide a
   candidate Psi mutation.
9. Current runtime records normalize, pose, corrected reraster, classify/compact,
   RGB inverse, solve/proof/commit, topology and diagnostics in one graphics-queue
   command buffer and permits only one such in-flight submission.

## 2. Frozen semantic invariants

1. Scheduling time, token budget, partitioning and interleaving never change Psi,
   validity bits, exact gaps, provenance, certificates or transition signatures.
2. FP proposes work only. Promotion, association, rejection, conflict, proof,
   transition validation and publication are checked Q16.48/integer decisions.
3. A source bundle surviving ingress owns immutable GPU payload. It contains no
   capture texture, prediction target or lease reference.
4. No transaction surviving ingress retains a capture or prediction ring lease.
5. Source evidence for a transaction is sealed. Later observations enter a later
   transaction/source epoch and cannot change an in-progress proof according to
   GPU timing.
6. Minimal certificates are selected once from the sealed source set using section
   30 lexicographic coalescing and fixed-point redundancy elimination. They are not
   incrementally minimized in scheduling order.
7. Bundle headers, source scratch and candidate arrays are bounded execution
   windows only. They are never semantic source/certificate caps. Every source in
   the complete sealed evidence set is consumed exactly once or retained through a
   generation-safe lossless spill handle. Exhausted scratch pauses the transaction;
   it never truncates evidence or publishes an incomplete proof.
8. Page/block/microtile boundaries remain storage/execution only. A publication
   group is defined by one affected carrier footprint, not by physical page layout.
9. Candidate transition validation reads candidate S16 state and exact evidence
   directly. The disposable topology cache is rebuilt only after publication.
10. Sensor acquisition never waits for inverse. Every frame that has acquired a
   sealed-bundle ticket is retained exactly until canonical absorption or explicit
   unresolved staging. A frame arriving before any bounded ingress header can be
   claimed is not silently reinterpreted as accepted evidence: ingress records one
   exact skipped-admission diagnostic and releases the capture lease. S4-10, not
   S4-08.3, supplies the durable lossless spill needed to guarantee admission for
   an arbitrarily long overload interval.
11. The implementation introduces no CPU scheduler, synchronous wait, GPU
    readback decision, second world, compatibility path or legacy kernel branch.
12. Overlapping carrier mutations are admitted and published in monotonic ticket
    order. Disjoint logical footprints may interleave, but GPU timing may never
    reorder two transactions that read or write an intersecting page/block mask.

## 3. Minimal runtime model

S4-08.3 uses one bounded transaction arena rather than separate physical queues for
each stage.

### 3.1 `SigmaTransactionGpu`

One generated C#/HLSL ABI record owns:

```text
logical transaction key
base Psi revision
publication manifest handle/generation
sealed source-bundle handle/generation
calibration epoch
pose-gauge fingerprint
independence/source keys
affected logical page references
affected 8x8 block mask
stage and opcode
current block and 16-sample microtile cursor
completed block/microtile state
scratch generation and proof slot
candidate-transition state
monotonic ticket serial
unresolved dependency fingerprint
```

`ticketSerial` is an unsigned 64-bit `uint2` value with checked exhaustion; frame
or session duration may not wrap scheduler order.

One local inverse transaction references at most four generation-safe logical page
handles (the 2x2 page neighbourhood a finite local carrier footprint can cross)
and carries four 64-bit block masks. A future operation with larger semantic
support must form explicitly validated commit groups; it may not add a variable
pointer/list traversal to this hot-path ABI.

The active transaction capacity remains the existing bounded live capacity of
eight. More locality waits in owned source/raw staging; increasing the active
capacity is not a performance fix.

The record also owns an exact logical read/write footprint mask. Admission chains
every intersecting transaction to the immediately preceding ticket; the successor
cannot evaluate against or publish over a base revision older than that dependency.
This is execution ordering only and never a carrier identity.

### 3.2 `SigmaSealedSourceBundleGpu`

The bundle reuses the existing proof/raw ABI instead of inventing another sensor
format. The current `SigmaProofSampleGpu.raw[0..5]` already stores the required
depth pixel/range/view-Z values and the four 2x2 RGB footprint samples. The current
`SigmaRawFrameRecordGpu` already stores timestamps, intrinsics, poses, source keys,
pairing health and the accepted pose-gauge append area.

Ingress moves construction of these bytes from the end of solve into the short
owned-packet extraction pass. The bundle owns:

```text
immutable frame/source/provenance keys
calibration epoch and accepted pose-gauge fingerprint
one copied SigmaRawFrameRecordGpu-compatible active frame record
references to existing 8x8 raw payload tiles (6 uint4/sample)
active-only compact prediction association payload
raw unresolved-tile handle when exact replay remains necessary
copied corrected Q16.48 depth/RGB calibration snapshot
generation-safe immutable cone-slope/ray-LUT epoch handle
```

One active prediction-association record stores, for each eye, only the copied
depth/support pair, signed-64 carrier page coordinate, generation/revision/segment
state key and carrier-local UV required by exact association. Pose-gauge normals
are consumed during ingress and are not retained. Global immutable ray/slope LUTs
may be referenced. Transient capture/prediction textures may not be referenced.

Memory ownership is split deliberately:

```text
durable/unresolved raw arena
    existing 4096 x 8x8 tiles x 6 uint4/sample ~= 24 MiB payload

active association arena
    only 8 active pages x 4096 samples x 2 compact eye records ~= 3--4 MiB
```

When evidence becomes dormant, its active association snapshot is released while
the raw tile and dependency fingerprint remain. Reactivation regenerates current
association from the raw tile and retained frame record. This avoids expanding
all 4096 raw slots with prediction-cache data and keeps transient scratch within
the section-34 budget.

Ingress first copies/compacts this payload on GPU, records a short completion
ticket for resource lifetime, then releases all source/prediction leases when that
ticket completes. The multi-frame transaction consumes only the owned bundle.

The copied calibration snapshot is approximately 704 bytes per bundle and is
interpretation metadata, not physical state. A referenced immutable slope/ray LUT
epoch cannot be reclaimed until every bundle/raw record that names its generation
has retired. Revalidation always uses this original source pose/calibration
snapshot; a later calibration epoch can only create a later source bundle.

There are 64 resident sealed-bundle headers backed by the existing unresolved raw
arena, with at most eight active transaction/association payloads. Both numbers
bound resident execution only. A header may retire after its generation-safe raw,
calibration and provenance handle has entered the transaction's source stream.
Additional sealed evidence remains in unresolved staging and is streamed through
the same transaction; it is never discarded or excluded from proof because all 64
headers are occupied.

### 3.3 Null-contact probation assembly

Each source bundle is immutable, but section-18 promotion may require more than one
bundle. A transient `SigmaProbationGpu` record may collect generation-safe bundle
handles in ascending source/ticket order before any inverse transaction is sealed:

```text
both depth eyes in one coherent bundle
OR one depth eye plus persistent calibrated RGB support
OR two temporally separated valid bundles with sufficient exact baseline
```

When one rule closes, the ordered bundle-handle set is frozen and becomes the
transaction's sealed source set. Before closure it is probation evidence only and
cannot publish geometry. Existing-carrier updates normally seal one bundle
immediately. This preserves immutable source sets without weakening the complete
null-to-contact support rule.

The probation and transaction ABIs reference a generation-safe segmented source
handle stream. A coherent dual-depth or depth+RGB bundle and a two-bundle temporal
baseline are sufficient *promotion witnesses*, not maximum evidence counts. Once
probation closes, every source already sealed for that transaction remains in its
ordered source stream and participates in exact proof. Fixed-size handle segments
are consumed through persistent cursors; segment exhaustion spills/pins the next
segment and pauses admission rather than truncating the set.

### 3.4 Work granularity

```text
canonical transaction : complete sealed evidence over affected carrier footprint
proof block            : 8x8 = 64 samples
execution microtile    : 16 samples x 16 S16 coordinates = 256 threads
```

One proof block is four execution microtiles. A persistent cursor prevents any
work from restarting at the beginning after an XR frame boundary.

### 3.5 Bounded admission state

The source side is a fixed generation-safe ring of at most 64 headers. Header
states are:

```text
FREE -> EXTRACTING -> READY -> PROBATION/ADMISSION_PENDING
     -> ACTIVE -> ABSORBED or DORMANT -> FREE
```

Ingress assigns a checked monotonic `ticketSerial` when it claims a `FREE` header.
The GPU scheduler performs two fixed bounded scans: first over the 64 source
headers to admit READY work, then over the eight active transaction slots to emit
execution work. There is no variable queue traversal and no CPU admission choice.

Admission compares exact logical page/block masks. Intersecting work is chained in
ticket order; disjoint work may occupy different slots and interleave. A probation
record keeps its ordered ticket set and receives one transaction ticket equal to
the first contributing bundle. Retiring a header never renumbers another ticket.

## 4. One deterministic scheduler

`ScheduleSigmaTransactions` performs exactly two bounded scans: 64 source headers
for admission and eight active arena records for execution. It updates a
deterministic deficit and emits compact opcode work lists plus indirect dispatch
arguments. Admission and execution use the same ticket ordering; neither scan is
allowed to become a CPU loop or an unbounded GPU queue traversal.

Ordering is fixed:

```text
budget class -> ticket serial -> logical carrier key -> source key -> block -> microtile
```

Budget classes are:

```text
INGRESS_ADMISSION
CANONICAL_PROGRESS
PROOF_TRANSITION_CLOSURE
DERIVED_READOUT
```

Every class receives a fixed minimum token share. Unused tokens flow to the next
class; proof/commit-ready work receives the first surplus so scratch is released.
Deficit aging guarantees that continuously arriving work cannot starve an older
transaction.

The scheduler consumes generated static cost units, never timing readback. Every
opcode cost is a conservative worst-case upper bound for one execution microtile;
data-dependent early exits may make it cheaper but never permit the scheduler to
issue additional work. If one opcode microtile exceeds the device maximum during
profiling, its execution manifest is split into a smaller fixed microtile before
acceptance rather than dynamically changing runtime physics.

### 4.1 Execution-cost generation

Extend generation with two inputs:

```text
OperatorCost
    existing generated algebra/operator counts

KernelExecutionManifest
    threads/workgroup
    operator-plan invocation counts
    fixed buffer reads/writes
    scratch traffic
    barrier count
    topology witness count
```

The combined generator emits the authoritative C#/HLSL `KernelCost[opcode]` table.
Current heuristic Section 44 byte constants are replaced by this manifest. Cost
metadata is execution-only and does not alter algebra/operator fingerprints.

The generated table also declares the maximum records, samples, candidate
certificates, transition edges and output bytes touched by one opcode. Startup
asserts every declared binding range against the runtime Vulkan storage-buffer
limit and the section-34 memory budget before canonical mutation is enabled.

Quest profiles choose only token budgets and maximum tokens per dispatch. The
first profile uses the graphics queue and a conservative canonical budget; actual
Section 44 counters validate, but never modify, scheduling.

## 5. Exact block evaluation and stereo association

Replace full-page `PromoteGaugePage` with bounded block/microtile execution. Do not
create a second global preflight pass and do not calculate a source cell twice.

Each sample produces one exact outcome:

```text
NO_EVIDENCE
    invalid sensor input; no canonical assertion

EXISTING_UPDATE
    exact source cells are compatible with one existing carrier footprint

NULL_PROMOTION
    no compatible carrier exists and exact independent support satisfies section 18

EMPTY_EXACT
    exact cells conflict; retain gap/provenance as unresolved evidence

TRANSITION_UNRESOLVED
    carrier identities/first-hit ordering disagree and require later support
```

Stereo cases are frozen as follows:

1. Both eyes predict the same generation-safe carrier footprint: exact existing
   update if admissible.
2. One eye predicts a carrier and the other predicts no contact: exact joint
   association decides whether the second eye supplies an inclusive cell to the
   same carrier, no constraint because of first-hit ordering, or evidence for a
   distinct null promotion.
3. Neither eye predicts contact: deterministic null-to-contact bootstrap using the
   existing joint L/R lift and section 18 probation.
4. Eyes predict incompatible carrier identities: never blindly allocate a new
   gauge. Apply exact first-hit ordering; if one view is occluded it contributes no
   cell, otherwise preserve conflict/transition evidence.

Prediction remains an association accelerator, never an existence condition.

The current null lift is generalized only over the sealed independent source set;
its algebra is not redesigned:

```text
one or two independent inclusive depth geometry cells
    -> exact componentwise geometry-row meet
    -> existing deterministic null projective lift
       (geometry rows constrained, generated hidden rows at their existing
        null-bootstrap value)
    -> optional RGB source-cell contraction of that same candidate
```

Dual-eye depth, one depth plus calibrated persistent RGB and two temporal depth
bundles therefore share one lift implementation. RGB alone never invents geometry.
The depth+RGB probation form closes only when the RGB cell has supported appearance
denominator, narrows at least one generated coordinate and carries a distinct
accepted independence key. The temporal form requires two exact depth cells from
the persisted baseline bins. There is no sensor sum or alternate commit path.

Outcome and reason masks are GPU-resident diagnostics and scheduler inputs only.
They do not become physical state.

## 6. Proof and canonical transition closure

Microtiles append exact source records to transaction scratch. They never perform
order-dependent certificate minimization.

After all affected blocks complete:

```text
sealed source records
 -> lexicographic sort/coalesce
 -> reverse lexicographic redundancy sweeps to fixed point
 -> minimal proof
 -> candidate-state revalidation
 -> candidate transition validation when required
 -> Publishable
```

Candidate transition validation evaluates the generated annihilator catalog,
associator and persisted independence/first-hit gates directly over candidate S16
and current neighbour generations. It shares pure exact math includes with the
derived topology builder but never reads `_TransitionCache` as authority.

Regular updates take a proven regular fast path. Contact/null or potentially
singular changes must set `CandidateTransitionClosed` before publication.

Candidate transition validation reads shadow candidate states for every page in
the same publication group and current manifest-resolved neighbour states outside
that group. It never mixes a candidate endpoint with a stale per-page current flag.

### 6.1 Lossless proof stream with bounded execution windows

Do not duplicate the existing approximately 25.7 MiB proof-sample arena. Each
active transaction reuses its current 784-byte-per-sample `SigmaProofSampleGpu`
work page sequentially over the complete source-handle stream:

```text
next source handle -> build every independent source plane
                   -> append a lossless candidate record/run
overwrite sample work page only after that source is journaled
repeat until sealed source-count closure
all sources closed -> canonical proof finalization
```

The twelve-candidate array is only the fixed local sort/merge/redundancy window.
Candidate records retain original `sourceClass`, `independenceKey`, temporal role
and raw-tile provenance. Sorted runs and keep/removal state are generation-safe,
segmented execution scratch; when resident scratch is unavailable, the raw source
handle remains the lossless authority and the transaction waits/spills instead of
dropping a candidate.

After the complete sealed set has been journaled, run stable canonical external
merge ordering, same-provenance coalescing and the section-30 reverse-order
redundancy sweep to a fixed point. Redundancy uses persistent prefix/suffix meet
state so each sweep is linear in the coalesced candidate stream while preserving
the specified sequential reverse order. A fixed candidate count is permitted only
if a generated algebra proof establishes it as a mathematical post-reduction upper
bound; no such bound is assumed by S4-08.3. Certificate slots are a compact storage
optimization: excess irredundant proof remains generation-safe raw-backed proof,
never truncated provenance.

### 6.2 Bounded proof and transition closure

Proof reduction/finalization advances one persistent 8x8-block cursor at a time.
Candidate transition validation similarly uses fixed 64-edge chunks; it may never
execute an affected page/group as one unbounded closure step.

For every changed transition, one bounded opcode evaluates the complete generated
168-action annihilator catalog. A later associator opcode is eligible only after
that annihilator prerequisite and its required neighbour state are complete. There
is no semantic candidate cap or witness truncation: exhausted tokens preserve the
cursor and continue in a later frame. Cross-page endpoints resolve shadow candidate
state inside the publication group and manifest-visible current state outside it.

After publication, derived topology consumes a compact GPU dirty-transition list
and indirect dispatch. The current C# `for workIndex` recording of a full topology
pipeline per page is deleted; C# records one fixed bounded graph only.

### 6.3 Commit-time dependency revalidation

A sealed prediction snapshot is proposal/proof input, not permanent visibility
authority. Before `Publishable`, compare every referenced carrier/first-hit
manifest generation with the transaction dependency vector.

```text
all dependency generations unchanged
    -> re-evaluate source cells/sectors from owned payload and continue

any dependency generation changed
    -> REVALIDATE_PENDING
    -> reraster current manifest-resolved Psi from the retained source pose
    -> rebuild active association from owned raw payload
    -> repeat exact first-hit/source/proof gates
```

Revalidation uses one scheduler-owned exclusive raster target, never one full MRT
per transaction and never a capture/prediction ring lease. `REVALIDATE` is a
generated costed opcode; at most one transaction owns this scratch target at a
time. It rerasterizes committed manifest-resolved Psi from the retained historical
pose/calibration snapshot, rebuilds association from owned raw samples, refreshes
the exact dependency vector and releases ownership. A stale prediction can
therefore never authorize a commit. Same-region writers are serialized by logical
footprint; dependency validation covers other carrier regions that affected the
sealed first-hit result.

## 7. Atomic revision visibility

One `SigmaPublicationManifestGpu` owns a generation-tagged publication group:

```text
revision
manifest generation
expected page count
completed page count
proof/transition closed flags
publication state
```

Every physical page slot has execution-only `SigmaPageVisibilityGpu` metadata:

```text
bornManifest       manifest handle/generation that introduces this page
retiredByManifest  successor handle/generation, or INVALID
```

The shared resolver is exactly:

```text
visible(page) = IsPublished(page.bornManifest)
             && !IsPublished(page.retiredByManifest)
```

For a replacement group, all new shadow pages receive `bornManifest=M` and every
superseded old page receives `retiredByManifest=M` while `M` is PREPARING. Readers
still see every old page and no new page. Proof and candidate-transition closure
then complete, all visibility records are written, and one final atomic
`M.state=PUBLISHED` flips the complete logical footprint. There is no interval in
which a reader can observe a page-wise mixture.

`SigmaPageVisible()` is one shared C#/HLSL ABI rule used by forward-readout current
compaction and halos, inverse prior/page lookup, proof/gauge demand, candidate and
derived topology, prediction and temporary XR readout. Per-page `_CurrentFlags`
is rebuilt from this resolver as a disposable compact cache and is never authority.
Direct single-page `SigmaCarrierWriteLease.Publish()` routes through the same
one-page manifest helper; no publication bypass remains.

Manifest capacity equals the decoded resident-page budget, with generation-safe
segmented storage below the Vulkan binding limit. Page metadata stores manifest
segment, slot and generation. One current publication group retains one manifest;
the slot is reclaimed only after every referenced page generation is superseded or
durably evicted. Multi-segment groups reference the same logical manifest handle.

Manifest/page slots are reclaimed only when no visibility record, active
transaction dependency/pin, unresolved tuple or queued GPU submission references
their generation. Reuse increments the manifest generation; a stale handle can
neither expose nor retire a page.

This gives genuine all-or-none visibility for a footprint spanning multiple
storage pages without assigning physical meaning to page boundaries.

## 8. Unresolved evidence and replay

`EMPTY_EXACT` and incomplete transition evidence become
`UnresolvedSourceEvidence`, not rejected observations.

Its dependency fingerprint includes:

```text
base Psi generation(s)
calibration epoch
pose-gauge fingerprint
independence-key set
support/proof generation
candidate transition signature generation
```

It is reactivated only when at least one dependency that can change the exact
result changes. Arrival of an equivalent frame alone does not resubmit it.

The fingerprint is a disposable lookup accelerator only. Exact dormancy and
reactivation compare the complete stored dependency tuple; a hash collision can
never suppress or authorize canonical work.

Each unresolved 8x8 tile stores up to eight unique generation-safe publication-
manifest handles in deterministic order. If its 64 samples reference more than
eight unique manifests, the tile records the exact global published revision as a
conservative dependency. This overflow may cause an extra revalidation after an
unrelated commit, but can never miss a relevant change or alter canonical output.

The bounded active arena spills unresolved owned raw tiles into the existing
generation-safe staging model. S4-08.3 must not claim unlimited durable session
length; S4-10 connects this exact spill format to asynchronous lossless flash
persistence and reclamation.

## 9. Submission and lifetime graph

The old one-in-flight monolithic graph is deleted. C# records a fixed graph; GPU
state decides whether indirect dispatch counts are zero.

```text
CB1 Sigma.Ingress
    normalize
    pose gauge
    corrected same-frame prediction
    FP proposal
    owned source-packet extraction
    short completion ticket for capture/prediction leases

CB2 Sigma.CanonicalQuantum
    transaction scheduling
    bounded exact microtiles
    proof/candidate-transition closure
    manifest publication

CB3 Sigma.Derived
    published dirty topology cache
    safe readout dirty compaction
    temporary stereo carrier preview
```

The initial implementation submits all three on the proven graphics queue.
Hardware async compute is out of scope until profiling proves it beneficial and a
separate fence/capability gate is accepted.

Separate command buffers provide lifetime and priority boundaries, not hardware
preemption by themselves. `CB1` is recorded in the existing pre-render ingress
path. The fixed `CB2`/`CB3` indirect graphs are submitted from one deterministic
URP end-frame hook after the current XR eye draw has been enqueued. Their token
limits, not the mere existence of three buffers, guarantee that they cannot consume
an unbounded interval before the next frame. The hook records the same graph every
frame and performs no CPU work selection.

Ingress tickets only protect copied source resources. Canonical transactions own
no ring leases. C# polls completion solely to retire leases/resources; it neither
selects work nor authorizes mutation.

The ingress completion ring has four slots, matching the existing prediction
target ring default. A slot contains only the short source-extraction ticket and
its raw/corrected leases. Failure to obtain a completed slot rejects that ingress
submission fail-closed without overwriting it, increments the skipped-admission
diagnostic and does not create a bundle ticket. Bounded CB2 work and the existing
eight-slot capture rings prevent canonical backlog from holding those slots.

Lifecycle semantics are fixed:

```text
Stop Scan
    stop new ingress admission
    let already submitted CB1 finish and release its ring leases
    continue bounded CB2 closure for already sealed/admitted transactions
    allow CB3 to publish safe derived readout
    preserve arena, tickets, cursors and Psi

Resume Scan
    restart CB1 admission without resetting canonical progress

OnDisable / OnDestroy
    stop recording new work
    register last ingress/canonical/derived completion tickets plus all owned
    resources with SigmaGpuRetirement
    release/reuse only after proven completion; never block
```

A completion polling fault quarantines the affected resources and disables further
canonical submission fail-closed. It is never interpreted as completion.

## 10. Readout safety and device observability

Only committed Psi renders as physical geometry.

```text
regular committed block
    -> immediate disposable readout

changed singular transition
    -> conservative no-bridge suppression
    -> derived topology cache ready
    -> disposable readout
```

Candidate, probation, unresolved and transition-pending states appear only in a
small GPU-rendered screen-space diagnostic strip. They never depth-write or look
like physical surfaces. Diagnostic bins distinguish at least:

```text
proposed
source bundle sealed
existing update
null promotion
empty exact meet
transition unresolved
proof closed
published
readout safe
```

This makes the blank-scan boundary visible without CPU readback. The temporary
direct carrier backend remains disposable and is replaced by S4-11 meshlets.

## 12. Deterministic implementation order

### Phase A — ABI, generated execution manifest and owned source bundles

1. Generate shared transaction/bundle/manifest ABI and exact strides.
2. Generate `KernelCost` from operator costs plus execution manifest.
3. Add GPU packet extraction from current capture/prediction inputs.
4. Split ingress completion lifetime from multi-frame transaction lifetime.
5. Add ordered section-18 probation records which seal immutable bundle sets only
   after exact independent-support closure.
6. Copy the corrected calibration snapshot and pin its immutable slope/ray-LUT
   epoch for exact replay.
7. Prove no arena/bundle record contains a capture/prediction texture or lease.

Gate: capture and corrected prediction leases retire after the short ingress
ticket while the owned bundle remains valid and replayable.

### Phase B — persistent arena and cost-token scheduler

1. Replace frame-local work records with eight generation-safe transaction slots.
2. Implement the 64-header bounded admission scan, exact footprint dependency

## 14. Scope and effort estimate

This is one concentrated execution-architecture repair, not another ontology
redesign.

Expected effort distribution:

```text
owned source payload and lease split       20%
transaction arena / scheduler              25%
block evaluation / mixed stereo            20%
proof / transition / publication           25%
derived readout / diagnostics / closure     10%
```

Expected production delta is approximately 1,900--2,800 net lines including the
generated ABI/cost output. Reusing the existing six-`uint4` raw sample payload,
frame record, one proof-sample arena and one exclusive revalidation target avoids
several otherwise duplicated multi-megabyte paths. The audited authoritative files
currently contain 12,497 lines before the new generated ABI/manifest/diagnostic
assets, so coherent whole-file replacement touches roughly 12,500--13,500 source
lines even though only one implementation survives. Focused fixtures add about
350--600 lines; control/generated graph changes add about 100--200 lines.

Difficulty is high but bounded: the hard proofs are sealed-evidence parity across
scheduling partitions, overlap-ticket ordering, stale first-hit revalidation,
bounded proof/transition closure and manifest-based all-or-none publication.
Relative scope is smaller than S4-08.2's algebra/lowering rewrite and larger than
one shader optimization. A realistic uninterrupted agent estimate is 18--28
focused implementation hours plus 2--4 hours for final compilation/device/archive
closure, assuming no new Unity/Adreno compiler defect. This estimate is not
acceptance evidence and does not authorize design changes.
