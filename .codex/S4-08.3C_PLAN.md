This run closes the concrete device-audit defects in the existing S4-08.3 graph.
It is not a redesign. It adds no second world, queue subsystem, transcript,
interpreter, CPU scheduler, fallback or heuristic acceptance gate.

## Frozen ontology

- `Psi : Sigma_2 -> S16` remains the only canonical physical state.
- All mutation/publication decisions remain exact checked Q16.48 plus validity and
  provenance. FP and telemetry never authorize work or mutation.
- Existing sealed bundles, transactions, proof stream, transition validation,
  revision manifest, dormant ownership and derived readout remain authoritative.
- Evidence/proof windows never become semantic caps; resident exhaustion cannot
  truncate evidence or publish partial state.
- Shader changes are coherent complete-file replacements after reading the whole
  file, includes, ABI, bindings and dispatch order. No compatibility branch remains.

## Intentionally small change surface

Production target: roughly 450–700 net LOC plus 150–250 focused test LOC. The only
new per-transaction storage is one transient `uint4 execution` (16 bytes, 128 bytes
at eight transaction slots). No new GPU arena or readback request is permitted.

`execution` has one fixed meaning:

```text
x = current source ordinal
y = (certificateBlock << 2) | executionMicrotile
z = completion bits for PREPARED | RGB_L | RGB_R | MET | FINAL
w = SIGMA_PROPOSAL_* bits | observed SIGMA_STREAM_OUTCOME_* mask |
    EXECUTION_FAULT
```

The bit layout is generated and disjoint: proposal bits remain 0–9, observed
outcome classes occupy bits 16–20 and `EXECUTION_FAULT` is bit 31. A generation
fixture rejects any future collision.

Transaction generation remains in the existing identity. A stage owns scratch only
when transaction slot+generation and `execution.xy` equal its immutable work item.
On transaction allocation, reuse, dormant replay and historical revalidation reset,
`execution` is reset before any scratch can be read.

The scheduler also sets one transient `ISSUED` bit before dispatch. If the same
owner tuple reaches a later scheduler round without all five completion bits, the
entire chain (including an otherwise invisible skipped Prepare dispatch) failed;
the transaction becomes FAILED instead of being silently reissued.

## C2 — generation-owned five-stage inverse

1. Scheduler emits one owner tuple in `execution.xy`, clears its phase bits and
   leaves accumulated exact proposal bits in `execution.w` for the transaction.
2. Prepare validates slot+generation+tuple, writes projective scratch, then sets
   `PREPARED`.
3. RGB-L and RGB-R require `PREPARED` and the same owner. Each sets its completion
   bit after writing its scratch; an unobservable source still completes with an
   explicit invalid/empty exact cell rather than stale bytes.
4. Meet requires PREPARED+RGB-L+RGB-R and sets `MET` only after all joint bounds,
   provenance, metadata and outcomes for the owner are written.
5. Final requires every prerequisite bit. Missing ownership/completion sets
   `EXECUTION_FAULT`, moves the transaction fail-closed, and never advances the
   source/microtile cursor. Successful final sets `FINAL`, ORs the existing exact
   proposal flags and the bit for its existing `SIGMA_STREAM_OUTCOME_*` into
   `execution.w`, then alone advances progress.
6. No new result ontology is introduced. Existing proposal flags and existing
   `NO_EVIDENCE`, `EXISTING_UPDATE`, `NULL_PROMOTION`, `EMPTY_EXACT` and
   `TRANSITION_UNRESOLVED` classes remain the exact outcome vocabulary.

## C3 — fail-closed closure and publication

The current proof and candidate-transition algorithms remain unchanged. Before
`PUBLISHABLE`, revalidation applies this exact gate:

```text
EXECUTION_FAULT                         -> FAILED; never publish
no SIGMA_PROPOSAL_ACCEPTED              -> DORMANT; retain exact evidence
only NO_EVIDENCE or EMPTY_EXACT          -> DORMANT/EMPTY_EXACT
TRANSITION_UNRESOLVED or open proof      -> DORMANT/UNRESOLVED
accepted EXISTING_UPDATE or NULL_PROMOTION
with closed proof/transition             -> publication candidate
```

For a newly allocated UNKNOWN page, the outcome mask must contain an accepted
`NULL_PROMOTION`; for an existing carrier it must contain an accepted
`EXISTING_UPDATE`. These are already-computed exact outcome facts, not new FP
thresholds. An existing update may publish accepted proof/provenance changes even
when `SIGMA_PROPOSAL_CHANGED` is zero.

Fix the existing page contract rather than inventing a span type:

- `transaction.publication.z` is the sole page count;
- initialize unused `page1..page3` references to explicit invalid handles;
- publication validates and visits exactly `[0, publication.z)`;
- never infer count by scanning zero-filled page records;
- the same accepted revision immediately creates its matching visible and
  `ReadoutDirty` generation; no second publication is required.

## C4 — bounded progress without changing token physics

Keep the existing scheduler, opcode lists, costs and deficits. Refactor command
recording only:

- `RecordCanonicalRound` records the existing schedule/dispatch chain once;
- one canonical command buffer records exactly eight rounds;
- budgets are refilled only in round zero; rounds 1–7 consume the same remaining
  deficits and therefore cannot exceed the current submission token budget;
- rounds 0–6 neither emit nor charge `PUBLISH_MANIFEST`; round 7 alone emits and
  dispatches publication, leaving that exact worklist intact for the existing CB3
  derived/readout handoff;
- visibility initialization and diagnostics run once per submission;
- transaction and source ordering are unchanged.

This removes the artificial one-dependent-opcode-per-XR-frame latency without
restoring a page-sized monster dispatch. Parity must hold for one versus eight
recorded rounds.

Ingress uses its existing bundle/raw ownership and indirect extraction. Remove only
the artificial two-bundle admission cap: seal every current candidate that fits in
the already-free resident bundle capacity. `SKIPPED_ADMISSION` may not mean silent
loss. If resident capacity is exhausted, increment the explicit exhaustion counter,
retain/fail closed according to existing ownership, and do not claim a successful
lossless run. Durable arbitrary overload is S4-10; the S4-08 device gate requires
zero resident exhaustion for its full run.

## C5 — temporary audit telemetry, no control dependency

Extend the existing once-per-second asynchronous ~3 KiB diagnostic readback. Do
not add another request or buffer. The 16-byte transaction addition is included in
the existing transaction-array readback.

Decode/log per live transaction:

- slot/generation/state/ticket and source/progress tuple;
- `execution.xy`, phase mask, accumulated proposal bits and fault bit;
- page count plus page0 source/target/generation;
- proof/transition/revalidation cursor and ownership already present.

Use the already-read `SigmaStreamDiagnosticGpu.memory` and `.reserved` words; these
UAVs are already bound by the owning passes, so inverse does not gain another UAV
and scheduler control does not become writable from canonical math:

```text
memory.x   phaseIncompleteFaultCount
memory.y   ownerMismatchCount
memory.z   acceptedFinalCount
memory.w   zeroAcceptedClosureCount
reserved.x publicationGateRejectCount
reserved.y ingressResidentExhaustionCount
reserved.z novelNullPageRejectCount
reserved.w reserved
```

Continue logging opcode work counts, deficits and budgets. Calculate diagnostic
load as generated token cost × already-read scheduled opcode count. Label existing
ingress/canonical/derived submission-to-completion measurements explicitly `wall`;
they are not per-kernel GPU timings. Host diagnostics may timestamp first accepted,
first publication and first non-zero draw from readback transitions. Nothing read
back may alter scheduling, evidence, proof, publication or rendering.

The temporary fields remain useful until S4-11 replaces direct carrier preview;
they can then be removed without changing canonical bytes.
