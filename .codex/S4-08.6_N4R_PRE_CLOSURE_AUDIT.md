# S4-08.6 N4R pre-closure authority audit

Status: `N4R STOPPED_AT_AUTHORITY_GATE`

Scope: only the semantic chain required to replace the N3 one-footprint bootstrap
with one coherent bounded full-frame close. This is not a new scanner design and
does not reopen unrelated N1/N2/N3 work.

## 1. Result

The frozen program constructs and proves:

```text
one coherent left/right footprint group
    -> one set-valued four-axis S16 preimage
    -> one full-S16 lifted state
    -> one relative level-zero cell at (0,0)
    -> global-translation normalization
```

It does not construct or prove:

```text
many simultaneous fresh footprint groups
    -> one finite relative Sigma_2 support pattern
    -> native relation attachments between its cells/components
    -> one observation/workgroup-order-independent normalized field delta
```

Therefore a production full-frame N4 implementation cannot legally assign more
than the already-proved single fresh cell. Pixel/tile coordinates, XYZ, hashes,
page/sample addresses, allocation order and workgroup completion order are not
valid substitutes. N4 runtime implementation remains stopped.

## 3. Source-backed boundary

The absence is explicit rather than inferred:

- `I_Q.freshBaseAdmission.scope` is
  `ALL_ZEMPTY_FIELD_ONE_COHERENT_FOOTPRINT_GROUP_AT_CHI0_KAPPA0`.
- Its `supportPattern` is one relative level-zero cell.
- `I_REP.freshSupport.baseCase` is one coherent footprint group -> one cell.
- `I_REP.gaugeFamily.independentComponentTranslation` is not admitted without a
  relation-program proof.
- `FRESH_BASE_PATTERN` in the generated IR has one lifted state and one verified
  relation as input.
- generated CPU fresh admission literally constructs only
  `SigmaGaugeCell(0,0,0,payload)`.
- `TryResolveFreshBaseAdmission(IEnumerable<branch>)` treats its enumerable as
  alternative preimages that must all yield the same one-cell result. It is not a
  set constructor for independent observations.
- the gauge proof checks order invariance for a pattern whose coordinates were
  supplied beforehand; it does not derive those coordinates.
- live N3/N4 scratch is `Observation=1`, `LiveFreshBranchCount=1`, two relation
  tuples and four representation deltas, and selects the centre pixel.

The N2 whole-query reducer can evaluate and reduce supplied work. It cannot fill
this gap because it does not generate a relative intrinsic placement for several
unattached supports.

## 4. Minimal missing theorem and generated operation

The smallest authority extension is one operation, not a placement manager:

```text
AdmitFreshSupportSet(
    published representation R_t,
    one coherent whole-frame observation Y_t,
    generated Merkaba program M,
    retained exact frontier/certificates C_t)
->
    ResolvedCommon(
        relative finite dyadic support pattern,
        full S16 values,
        native relation attachments,
        minimized certificates,
        normalized NativeGaugeDelta + NativeStateDelta)
  | Unresolved(exact disjunction/frontier)
```

The theorem must constructively define:

1. which reduced footprint groups refer to existing support and which remain
   unattached, using whole-query support evidence rather than a winner;
2. how a native relation witness yields an exact relative `Sigma_2` relation or
   displacement for newly attached cells, including bracket/context ownership;
3. how disconnected components are placed: either their relative placement is
   supplied by the generated native relation law, or independent component
   translation is proved harmless and assigned a canonical normal form;
4. how all surviving support/placement disjunctions produce one common normalized
   finite field delta or remain unresolved;
5. why observation order, footprint enumeration, tile size, workgroup count,
   allocation order and backing layout cannot change normalized bytes;
6. how the minimized frontier/certificate is a sufficient exact input to every
   later close, so absorbed raw evidence can be reclaimed without changing any
   future feasible-set decision.

The missing native datum is not a numeric tolerance. It is the constructive map
from a proved multi-support relation context to relative two-dimensional carrier
incidence/displacement (or an exact theorem that such relative component placement
is harmless gauge). The current K16 relation classifier alone says whether a
supplied tuple is admissible; it does not choose that map.

Required generated IR shape:

```text
WHOLE_FRAME_REVERSE_SET
    -> SUPPORT_EQUIVALENCE_DISJUNCTION
    -> NATIVE_RELATIVE_SUPPORT_RELATIONS
    -> FRESH_SUPPORT_SET_PATTERN
    -> GAUGE_NORMALIZE
    -> COMMON_FIELD_DELTA_OR_UNRESOLVED
    -> CERTIFICATE_MINIMIZE
```

This stays one semantic `NativeCloseCommit`. GPU project/evaluate/reduce/contract,
relation worklists, compaction and overflow remain lowering stages only.

## 5. Smallest corrective N1/N2 extension

### Corrective N1 authority/codegen

- freeze the relative-support/independent-component theorem above in `I_Q/I_REP`
  and, only if it is genuinely native algebra, the scanner algebra capsule;
- add the single set-level IR operation to the sole generated program;
- emit executable CPU/HLSL descriptors for relation-candidate construction,
  common normalized field-delta selection and certificate re-entry;
- retain exact ambiguity; do not add a pixel/XYZ/hash/page placement fallback;
- regenerate the program and fingerprints.

No live runtime mutation and production `+0/-0`.

### Corrective N2 oracle

Prove CPU/Vulkan parity from coherent multi-footprint observations for:

- two and many fresh supports with one unique relative pattern;
- equivalent discovery/workgroup/tile permutations -> byte-identical result;
- non-equivalent relative placements -> no mutation;
- mixed existing/fresh/unchanged/contracted/unresolved supports;
- disconnected components under the newly frozen theorem;
- regular, exact-ZD, nonassociative, fold/two-sheet and unresolved attachments;
- cross-workgroup/cross-tile continuation equal to one exhaustive solve;
- minimized certificate restart/re-entry equal to exhaustive retained evidence;
- no per-pixel, XYZ, hash, allocation or backing identity in the semantic result.

Production remains `+0/-0`. Only after these gates pass may N4 consume the
generated operation in a bounded full-frame GPU graph.

## 7. Performance constraint on the eventual lowering

The corrective theorem does not authorize a larger orchestration graph. The live
full-frame lowering must remain:

```text
complete coherent footprints
    -> parallel validity/query worklist
    -> whole-query support reduction
    -> exact reverse worklist
    -> native relation/set closure
    -> GPU certificate/frontier compaction
    -> compact state/gauge deltas
    -> one root-last publication
```

Tiles/workgroups are execution partitions only. Cross-tile relations use the same
bounded continuation. Cardinality changes workgroups and indirect dimensions, not
one dispatch per pixel/support/relation/page/sort level. No serial full-frame
interpreter is admissible. The N4 `D_budget<=64` gate remains independent of time.

## 8. Disposition

- N3 remains the accepted one-footprint bootstrap.
- `efe59f6` and the current dirty N4 tree are forensic evidence, not an accepted
  N4 checkpoint.
- no further N4 production edits are authorized until the corrective authority
  and oracle gates above close.
- the current N4 certificate/refinement fixes must be preserved, then rebased onto
  the generated set-level operation rather than extended with helpers.

## 9. Exact authority input required from the native theory

No implementation choice is requested. The corrective authority needs explicit
answers/equations for these semantic questions:

1. Given two or more newly supported full K16/S16 modes and their complete
   bracketed Merkaba relation context, what exact predicate proves that two
   supports have intrinsic incidence, and what exact map yields their relative
   dyadic `Sigma_2` displacement/incidence record?
2. If the relation supplies a set of admissible relative incidences rather than
   one value, what is that set and which complete-loop/plaquette law contracts it?
   Non-singleton non-common results must remain unresolved.
3. For relation-disconnected supported components, is independent translation in
   `Sigma_2` harmless gauge? If yes, define its equivalence group and constructive
   canonical normal form. If no, such components cannot receive canonical
   relative placement until later relation evidence connects them.
4. Besides the already admitted global translation, are rotation, reflection,
   axis permutation or dyadic scale transformations gauge-equivalent? The exact
   admitted group and tie-breaking normalization must be frozen.
5. How do fold/two-sided/null-contact/near-singular/nonassociative relation classes
   constrain incidence without collapsing distinct supports? A class label alone
   is not a displacement rule.

The required answer may be a generated algebraic formula, a finite exact relation
table or a theorem that a stated gauge quotient makes some placement immaterial.
It may not be an implementation heuristic. Everything else in the corrective
N1/N2 slice follows mechanically from this authority input.
