Authority: `new_spec.md`, `CPQ4-2026-08-24-S16-v7`.

## 1. Objective

Replace the live page/bundle/transaction/token workflow with one fixed GPU dataflow
from a complete coherent rig observation into one atomic sparse `Psi` revision.
Reuse the proven exact S16 primitives and carrier storage. Do not repair, rename or
wrap the old streaming lifecycle.

The accepted endpoint is:

```text
coherent RGB_L/R + DEPTH_L/R + exact pose/calibration
    -> complete owned observation
    -> current/pending candidate proposals
    -> four independent exact source-cell streams
    -> exact target grouping and S16 meet/lift
    -> exact pending continuation/reuse/promotion
    -> complete evidence journal
    -> changed-edge transition closure
    -> shadow carrier scatter
    -> one atomic frame-revision root publication
    -> disposable prediction/XR readout
```

## 2. Frozen invariants

- `Psi : Sigma_2 -> S16` is the only canonical physical world.
- Q16.48 checked nearest-even values, outward intervals, validity, gaps,
  provenance and generated bracketed S16 operators are unchanged.
- `D_L`, `D_R`, `RGB_L`, `RGB_R` remain independent until exact max/min meet.
- First-hit evidence has exactly zero post-hit effect; UNKNOWN is never EMPTY.
- Prediction, pending readout and optical adjacency propose work only. Exact inverse
  admissibility decides identity, continuation, promotion and mutation.
- Page/block/workgroup/proof-window dimensions are execution/storage only.
- No fixed resident or scratch capacity may truncate a coherent observation,
  evidence journal, proof or provenance.
- No CPU pixel loop, CPU canonical scheduler, synchronous readback, timing-driven
  mutation, second world, legacy fallback or compatibility branch.
- Every changed/new shader is read as a complete program and emitted as one complete
  file. No hotfix editing of retired streaming shaders is permitted.

## 3. Forensic contracts this run must close

The current 320x320 input becomes 25 canonical-looking pages, duplicates those
pages through fresh Morton identities, loses later directional evidence at 64
resident bundles, and hard-stalls after 4096 durable raw blocks. The token/page
workflow also delays first visibility by tens of seconds and its Release GPU
recorders return zero samples.

These are one execution-model failure, not independent patches:

```text
execution tile -> identity -> proof owner -> page closure -> publication
```

The direct graph removes that authority chain. Acceptance is not obtained by
raising 64/4096/12, changing token prices, changing Morton order or weakening
transition/proof gates.

## 7. Generated ABI — exact resource ownership

One generator owns C#/HLSL strides and fingerprints for:

```text
SigmaOwnedFrameGpu
    frameRevision, calibrationEpoch, dimensions, four independence keys,
    pose-result generation, corrected-calibration generation, state, source cursor

SigmaFrameCandidateGpu
    source footprint ordinal, proposal kind, canonical/pending handle,
    exact carrier address when canonical, local pending coordinate otherwise

SigmaFrameOutcomeGpu
    accepted/unchanged/conflict/exclusion/pending masks, validity, gap/provenance refs

SigmaPendingGaugeGpu
    generation-safe handle, first revision/provenance key, local extent,
    evidence range, dependency generation, promotion state

SigmaFrameDeltaGpu
    resolved carrier address, prior generation, candidate state range,
    exact outcome/evidence range

SigmaDirtyEdgeGpu
    canonical endpoint addresses, shadow endpoint generations, claim kind

SigmaFrameRevisionGpu
    revision/base revision, changed-page range, evidence range,
    transition-witness range, publication state
```

Large Q16.48 cells use segmented structure-of-arrays buffers:

```text
SourceLo[source][coordinate][footprint]
SourceHi[source][coordinate][footprint]
SourceValidity[source][coordinate][footprint]
SourceProvenance[source][footprint]
```

At 320x320 all four complete 16D lo/hi streams are materialized once. They are both
inverse input and the complete foreground evidence journal; no bundle-owned copy is
made. Every binding remains below runtime Vulkan range through existing segmented
pool helpers.

## 8. Fixed direct GPU graph

The host records the kernels below in this order. Kernel splitting is fixed by
register/UAV legality and never selected by evidence values or CPU timing.

### A. Seal and proposals

1. Existing depth normalization and pose-gauge/reraster complete for one retained
   coherent frame.
2. `ClearFrameState` initializes all counts/generations for the owned frame.
3. `BuildFrameProposals` emits candidate keys from:
   current manifest-visible prediction, pending disposable readout, exact latent
   continuation proposal, then NOVEL.
4. Proposal order is current carrier address, pending key, NOVEL. FP/raster results
   cannot accept a candidate.

### B. Exact source cells

5. `BuildDepthSourceCells` runs for L and R.
6. `BuildRgbSourceCells` runs for L and R.
7. Mapping is coordinate-major: 256 threads = 16 footprints x 16 S16 coordinates.
8. Mixed-eye/no-prediction cases remain records; they are not rejected by proposal
   shape. Missing/uninformative sources contribute unconstrained valid intervals.

### C. Exact target resolve

9. `EvaluateCandidateMeets` tests every proposal with the same prior/four-source
   exact meet and immediately constructs its provisional deterministic S16 state:
   minimum-change prior lift for existing contact, exact null-to-contact lift for
   novel contact. It emits compatible target records and explicit empty-meet gaps.
10. `CompactResolvedTargets` stable-compacts by outcome.
11. Existing targets stable radix-sort by signed carrier address and reduce using
    componentwise max(lo)/min(hi), source-order provenance ties and prior meet.
12. Novel records remain in the deterministic local optical reference domain.

### D. Pending connectivity, reuse and promotion

13. `BuildPendingEdges` proposes four-neighbour local edges only for supported novel
    records; no image tile is formed.
14. `ClosePendingEdges` applies exact S16 regular/singular/no-claim rules.
15. Stable components use only exact claimed edges. Component ordinal is the
    lexicographically first accepted local coordinate.
16. Existing pending candidates are reused only after exact meet/first-hit support.
17. Promotion events sort by `(frameRevision, complete provenance key,
    componentFirstCoordinate)`.
18. The append-only extent allocator maps each component bounding local rectangle
    into the next collision-free `Sigma_2` extent with a persisted 16-sample
    unobserved guard on every side. The guard makes no null-transition claim.
19. Allocation happens once, after independent-support closure. No Morton remains.

### E. Exact candidate and evidence closure

20. `FinalizeFrameCandidates` reduces all records assigned to the resolved
    canonical/pending target, rebuilds the final joint cell/state, preserves
    width-derived information mass and revalidates every source cell. The
    provisional state from step 9 is never published directly.
21. The complete source-cell stream plus provenance is the immutable live commit
    journal. No proof minimization or 12-record window blocks foreground state.
22. Unresolved raw references name the owned frame/source footprint once; multiple
    constraints share that reference.

### F. Intrinsic transition closure

23. `BuildDirtyEdges` emits only edges incident to changed/new candidate samples.
24. Endpoint resolution is full shadow revision, then published base revision, then
    UNOBSERVED. Page boundary never appears.
25. Claim kinds are `NONE/CONTACT/PROVEN_NULL/CONFLICT`; state stays S16.
26. NONE/UNOBSERVED never requests singular closure. Claimed potential singular or
    contact/null edges run the exact generated annihilator/associator gate.
27. An unresolved claimed edge monotonically defers only its incident changed
    mutation(s). Deferred samples revert to prior state; dirty edges are repeated to
    a fixed point through one GPU continuation cursor. No whole-page failure bit.

### G. Shadow scatter and publication

28. `CompactChangedTargets` yields resolved carrier addresses only.
29. `PrepareFramePages` locates/clones/allocates backing page generations for all
    touched addresses. Page order is stable but non-semantic.
30. `ScatterFrameDelta` writes accepted non-deferred states and evidence ranges.
31. `CloseFrameRevision` verifies complete source/journal/transition/scatter counts.
32. `PublishFrameRevision` performs one atomic current-revision root flip over a
    variable-length changed-page manifest. Readers never inspect partial flags.
33. Dirty prediction and temporary XR point readout become visible from that same
    revision without waiting for a second publication or proof minimization.

## 9. Proof, raw ownership and persistence boundary

- The owned source-cell arrays are a complete exact live proof until compacted.
- Background `MinimizeEvidence` uses stable coalescing and reverse-order redundancy
  to fixed point over a segmented cursor. Window size cannot change output.
- The owned frame is released only after every needed record became a certificate
  or its raw footprint was transferred once to generation-safe ledger ownership.
- The raw allocator uses live-bit/free-list reuse and segmented growth; no monotonic
  4096/8192 cursor is legal.
- S4-08 must sustain the physical three-minute run without loss or growth. S4-10
  adds durable flash overflow for week/city-scale backlog; no finite RAM claim is
  presented as infinite persistence before S4-10.

## 13. Mandatory parity/physical gates

1. One 320x320 frame never creates a 5x5 identity/publication board.
2. Same frame under 8x8, 16x16 and alternate legal execution partitions produces
   byte-identical `Psi`, validity, gaps, provenance and proof.
3. Backing page boundary crossing equals an intra-page transition bit-for-bit.
4. Scratch proof windows 4/8/12/32 produce one identical fixed-point proof.
5. More than 12 source records and more than 8192 retained raw tiles continue.
6. Ten repeat observations before promotion reuse one pending gauge.
7. Revisit of supported wall updates existing carrier without a new extent.
8. Side reveal continues the compatible wall or creates an exact distinct pending
   component; image direction/tile never decides.
9. Thin 5 mm parallel surfaces remain distinct preimages.
10. Multi-page frame revision is all-or-none for prediction and XR readout.
11. First visible exact support occurs within five seconds and then advances every
    accepted revision; final target is one/two completion fences, measured on Quest.
12. Three-minute scan has no partial frame loss, duplicate-gauge loop, capacity
    cliff, missing binding, fence fault, stale scratch or growing unowned backlog.
13. Release profiler reports non-zero per-kernel timings or explicit unsupported
    capability plus external KGSL evidence; zero blocks cannot be called success.
