# Final Quest pipeline delivery

Final delivery runs after the complete source DAG and host gates. A native
compile check is not an APK or device acceptance. No production keys are
generated by these scripts; supply the existing authorized key securely.

User-authorized functional checkpoint (2026-09-11):
`QIS_APK_PURPOSE=FUNCTIONAL_TEST QIS_PIPELINE_MODE=CAPTURE Tools/unity/build_merkaba_apk.sh`
defers instruction/dispatch performance acceptance only. Hard shader/ABI gates
still apply. It reuses the existing Android debug key, permits manufacturing
driver compilation, and is not a BINARY_ONLY release or a no-JIT claim.
Use a separate QIS_MERKABA_BUILD_DIR/QIS_MERKABA_APK_PATH for this artifact.
Default RELEASE behavior still requires every performance/signing gate.

1. Set `QIS_RELEASE_KEYSTORE`, `QIS_RELEASE_KEY_ALIAS`,
   `QIS_RELEASE_STORE_PASSWORD`, `QIS_RELEASE_KEY_PASSWORD`. Do not put their
   values in a command log or commit. If a HOT shader exceeds 20k instructions,
   `QIS_ADRENO_EVIDENCE` must reference the exact-payload zero-spill/GPR/I-cache
   review consumed by `validate_merkaba_hot_path.py`. The 9–11 observation
   dispatch and hard shader/ABI gates cannot be waived by that receipt.
2. `QIS_PIPELINE_MODE=CAPTURE Tools/unity/build_merkaba_apk.sh` prepares the
   final Unity scene/configuration and creates the manufacturing APK. Archive
   the APK and its `pipeline-manifest.json`. Install only on the authorized
   matching golden Quest after the host gates. This is the sole driver-compile
   manufacturing mode, never the release behavior.
3. Retain the entire log from before launch, including the global key and
   every `Merkaba pipeline required:` line. Exercise scan, view, stereo/FFR,
   UI, paint/objects, FINE/ERASE, OPEN, export/viewer and lifecycle states.
   The interceptor captures native and Unity compute/graphics requests.
   Unity GraphicsStateCollection records coverage; it is not a warm-up cache.
   Focus loss and every 30 seconds flush `unity.graphicsstate`.
4. Retrieve the app-specific manufacturing output with adb from
   `/sdcard/Android/data/com.genesis.questmerkabascan/files/MerkabaPipelineCapture/`.
   Set `QIS_PIPELINE_CAPTURE_DIR` to the current source-hash directory,
   `QIS_PIPELINE_REQUIRED_LOG` to the complete capture request log, and
   `QIS_PIPELINE_GRAPHICS_TRACE` to its `unity.graphicsstate`.
   Interrupted/failed pipeline captures cannot satisfy the request inventory.
5. Do not edit sources or re-prepare the Unity scene between capture and
   release. `QIS_PIPELINE_MODE=BINARY_ONLY Tools/unity/build_merkaba_apk.sh`
   reuses the frozen prepared project, verifies all source/asset/native-SPIR-V
   hashes, packs the exact global-key PSO binaries, builds ARM64 IL2CPP,
   aligns to 16 KiB and signs explicitly. A changed input requires a new
   manufacturing capture, never a release SPIR-V fallback.
6. `verify_merkaba_apk.sh APK MANIFEST` verifies signature, alignment,
   package ID, ARM64 ELF, native/bundle/source hashes and embedded manifest.
   Archive its output and APK SHA-256. The PSO inventory check proves only
   the exercised scenarios; do not label it proof of unvisited render states.
7. Perform the authorized clean release install/cache-clear acceptance.
   Require `globalKeyMatch=1`, `pipelineBinaryMiss=0`,
   `nonBinaryPipelineAttempt=0`, `runtimeCompileFallback=0`, actual visible
   scan/draw and the full sustained/lifecycle/persistence/export acceptance.
   Unsupported driver/global key or missing PSO is a hard initialization
   error. Neither embedded SPIR-V nor a pipeline cache is a fallback.

`build_merkaba_vulkan_timestamps.sh` alone defaults to a compile-only empty
binary pack. This allows C++/shader compilation before capture; the APK builder
explicitly forbids shipping that payload. It cannot run a scanner on a device.

Reference semantics: [pipeline binaries](https://docs.vulkan.org/features/latest/features/proposals/VK_KHR_pipeline_binary.html),
[maintenance5 features](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceMaintenance5Features.html).
Driver binaries require a compatible manufacturing driver; this is not a PC
Adreno cross-compiler or a promise that a SPIR-V APK is already driver-compiled.
