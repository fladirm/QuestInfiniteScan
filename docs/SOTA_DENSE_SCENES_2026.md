# SOTA review: dense organic scenes and headset-aware readout for the Quest 3 surfel scanner (2026-09-14)

Scope: strengthen the surfel-scanner contract for a flower-shop class of scene (millions of small surfels, foliage, moving leaves, glass/cellophane) and the headset-aware readout (HZB occlusion from own depth + Environment Depth, foveated LOD error, temporal reuse). Every claim carries a URL, a date (publication date, or "acc." = accessed 2026-09-14 when the page is undated) and a classification: [OFFICIAL] vendor/standard documentation, [PEER-REVIEWED] published venue, [COMMUNITY] developer blog/forum/repo, [UNVERIFIED] preprint or second-hand claim not confirmed against a primary source.

---

## A. Derived cluster hierarchies with screen-space-error traversal and a bounded budget

**Classic point hierarchies.** QSplat (SIGGRAPH 2000) uses a bounding-sphere hierarchy with one point per node; a single structure serves frustum culling, backface culling, LOD selection and rendering (https://gfx.cs.princeton.edu/pubs/Rusinkiewicz_2000_QAM/index.php, Jul 2000) [PEER-REVIEWED]. Sequential Point Trees (SIGGRAPH 2003) replaced hierarchical traversal by sequential GPU processing of a linearised hierarchy, freeing the CPU (https://dl.acm.org/doi/10.1145/882262.882321, 2003) [PEER-REVIEWED]. Potree's out-of-core octree builder reaches 6-9 Mpts/s with hierarchical counting sort and per-node minimum-distance sampling (https://www.cg.tuwien.ac.at/research/publications/2020/SCHUETZ-2020-MPC/, CGF 2020) [PEER-REVIEWED].

**Continuous LOD for VR points.** Schütz, Krösl, Wimmer (IEEE VR 2019) eliminate chunk-wise popping by a single compute "reduce" pass that selects points per frame from an in-core array: 86 M points are reduced to 5 M in 5.45 ms on a GTX 1080 (16-17 M points/ms); density is reduced towards the periphery for VR, and per-point popping is hidden by growing points in over a blend range (blendRangeFactor 0.8, i.e. the user must move 20 % closer before a point reaches full size) (https://www.cg.tuwien.ac.at/research/publications/2019/schuetz-2019-CLOD/, 2019) [PEER-REVIEWED]. The follow-up software rasteriser batches 10,240 Morton-ordered points, uses adaptive coordinate precision (4 bytes/point for most points), and supports LOD nodes as variable-size batches to hit VR rates for 2 G points (https://arxiv.org/abs/2204.01287, Jul 2022) [PEER-REVIEWED].

**Nanite (Karis, Stubbe, Wihlidal, SIGGRAPH 2021 Advances).** Clusters are 128 triangles; the DAG is built by group -> merge -> simplify -> split. The runtime LOD test is purely local: each cluster stores its own error and its parent's error (unioned per group with shared sphere bounds), so the cut is found without traversing the DAG; a BVH8 over cluster groups is walked by a persistent-threads kernel with one shared job queue; occlusion is two-pass against an HZB (draw last frame's visible set, build HZB, test the remainder) and the culling test uses the previous frame's transforms (https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf, 2021) [OFFICIAL].

**Gaussian-splat LOD 2024-2026.** Kerbl et al. (SIGGRAPH 2024, TOG 43(4)): node granularity ε(n) = projected length of the longest AABB axis; the cut is the set of nodes with ε(n) ≤ τ (e.g. 1 px). Because a parent's AABB is never smaller than a child's, the cut is found in constant time per node in parallel. Smooth transitions interpolate position/colour/SH linearly, scale and rotation separately, and correct child opacity so the blend equals the parent at transition start; τ = 3/6/15 px are their quality levels, with 30+ FPS (τ=3) and ≈60 FPS (τ=6) on an A6000; cut/expand runs asynchronously and is updated every 2 frames; the hierarchy costs 400 B/Gaussian (69 % more than 3DGS) (https://repo-sam.inria.fr/fungraph/hierarchical-3d-gaussians/, Jul 2024) [PEER-REVIEWED]. Octree-GS assigns anchor Gaussians to octree levels and selects levels per view for consistent real-time rates (https://city-super.github.io/octree-gs/, TPAMI 2025) [PEER-REVIEWED]. LOD-GS targets detail-preserving anti-aliasing across LOD (https://arxiv.org/pdf/2507.00554, Jul 2025) [UNVERIFIED preprint]. Virtualized 3D Gaussians (SIGGRAPH 2025) copies Nanite's cluster design for splats: offline "local splatting" builds coarser clusters, an online footprint test selects perceptible clusters under a user tolerance, demonstrated on 0.1 G Gaussian composed scenes (https://arxiv.org/abs/2505.06523, May 2025; https://dl.acm.org/doi/10.1145/3721238.3730602) [PEER-REVIEWED].

**VR/mobile results.** VRSplat achieves 72+ FPS without popping/floaters but renders on an RTX 4090 and only displays on a Quest 3 (https://arxiv.org/abs/2505.10144, May 2025; https://dl.acm.org/doi/full/10.1145/3728311) [PEER-REVIEWED]. Atlas (arXiv 2 Sep 2026) reaches 70.9 FPS for city-scale splats only with a dedicated accelerator (18.5x over a mobile GPU), but its temporal-aware LoD search is directly reusable: consecutive frames share >99 % of selected Gaussians, so the cut is refined incrementally rather than re-traversed (https://arxiv.org/abs/2609.02352, Sep 2026) [UNVERIFIED preprint]; its predecessor Nebula (ASPLOS 2026) adds stereo rasterisation that maps left-eye splats to the right eye bit-accurately (https://arxiv.org/pdf/2512.20495, Dec 2025) [PEER-REVIEWED]. A community VR splat plugin claims stable 72 FPS on Quest 3 up to ~400 k Gaussians (https://github.com/ninjamode/Unity-VR-Gaussian-Splatting, acc.) [COMMUNITY/UNVERIFIED]; Unity forum reports for the same period are "pretty slow" (https://discussions.unity.com/t/3d-gaussian-splats-on-quest-3/1542816, Jan 2025) [COMMUNITY]. No peer-reviewed standalone-Quest result with millions of primitives at 72-90 Hz was found.

**Implications for the contract**
- Node payload (Nanite/Kerbl pattern): bounding sphere or AABB extent, own error, parent error (unioned per sibling group), child range, primitive range. The LOD decision must be a local test `err(n) ≤ τ < err(parent)` so no DAG walk is needed.
- GPU passes without CPU sync: (1) persistent-threads BVH8/octree walk with a device job queue producing candidate clusters; (2) local cut test + HZB test; (3) compaction into an indirect draw/dispatch (VK_KHR_draw_indirect_count is available on Quest 3, see H). Read back only a stats word.
- Budget: adopt a fixed total-load budget solved on GPU (Zhang & Peng 2026, section C) rather than a fixed τ; auto-raise τ when the compacted count exceeds the per-eye budget (Kerbl's VRAM auto-regulation is the same idea).
- Popping: geomorph over the ε interval (Kerbl) or a 0.8 blend-range growth (CLOD); update the cut every 2 frames and reuse >99 % of it (Atlas).
- Sizing: derive the per-eye surfel budget empirically; the only verified mobile-class data point (CLOD: 17 M points/ms reduce on a GTX 1080) does not transfer to Adreno 740, so the contract must expose the budget as a tunable with a measured default, not a constant.

## B. Coverage-preserving far LOD for foliage and thin structures

Alpha-mip coverage loss and its fix (scale mip alpha so the coverage at the test threshold stays constant) are documented by Castaño (http://www.ludicon.com/castano/blog/articles/computing-alpha-mipmaps/, 2010) [COMMUNITY] and shipped in DirectXTex `ScaleMipMapsAlphaForCoverage` (https://github.com/microsoft/DirectXTex/wiki/ScaleMipMapsAlphaForCoverage, acc.) [OFFICIAL] and Unity `mipMapsPreserveCoverage` (https://docs.unity3d.com/ScriptReference/TextureImporterSettings-mipMapsPreserveCoverage.html, acc.) [OFFICIAL]. Hashed alpha testing (Wyman & McGuire, I3D 2017) replaces the fixed threshold with a stable hash of world position and scale, which stops distant alpha-tested geometry from vanishing and extends to alpha-to-coverage (https://cwyman.org/papers/i3d17_hashedAlpha.pdf, Feb 2017) [PEER-REVIEWED]. Hybrid mesh-volume LoDs (Loubet & Neyret, CGF 36(2)) separate macroscopic surfaces (kept as mesh) from sub-resolution geometry (pre-filtered volumetric normal distributions and albedo) at each scale (https://onlinelibrary.wiley.com/doi/abs/10.1111/cgf.13138, May 2017) [PEER-REVIEWED]; Zhou et al. generalise this to an Aggregated BSDF per voxel with a closed-form factorisation (https://dl.acm.org/doi/10.1145/3708343, TOG 44(1) 2025) [PEER-REVIEWED].

Nanite Foliage (UE 5.7 preview Oct 2025; docs for 5.8, Experimental) converts triangle clusters into voxel bricks when simplification error favours it ("at most 128 4x4x4 voxel bricks" per cluster), stores a distribution of normals per voxel with per-pixel stochastic selection, and bins voxel clusters separately, sorted into depth buckets and drawn front-to-back for early-Z; Assemblies micro-instance up to 65 k parts (one tree 3.5 GB -> 29 MB) (https://dev.epicgames.com/documentation/unreal-engine/nanite-foliage, acc.; https://digitalproduction.com/2025/10/17/unreal-5-7-preview-pcg-grows-up-foliage-gets-fancy/, Oct 2025) [OFFICIAL]. On Adreno, Qualcomm's guidance is that fragment shaders using `discard` cannot contribute to LRZ during the binning pass and that alpha blending is preferred over discard (https://docs.qualcomm.com/bundle/publicresource/topics/80-78185-2/mobile_best_practices.html, acc.) [OFFICIAL].

**Implications for the contract**
- Aggregation rule for surfel clusters: when merging N leaf surfels into one far node, store `coverage = Σ leaf area / node footprint` (clamped) and a normal distribution (mean + spread), not an opaque disk. This is the Loubet/Nanite-voxel principle applied to surfels and preserves gaps between leaves/stems.
- Far-node rendering: hashed (world-position, node-id keyed) coverage test instead of blending, so distant foliage keeps its density without the coverage collapse of alpha mips; the hash must be stable across the LOD switch.
- Tiled-GPU cost: keep near/mid surfels in an opaque pass without discard (LRZ intact); put hashed-coverage far nodes in a separate front-to-back-sorted bucket, exactly as Nanite Foliage bins voxel clusters.
- Thin structures (stems, wire, glass edges): mark nodes whose children are anisotropic; never let their merged footprint drop below 1 px in the coverage estimate (minimum coverage floor).

## C. Occlusion with hierarchical Z on mobile/VR, depth sensors as occluders, foveated LOD

Two-pass HZB (previous-frame visible set -> HZB -> test rest) is the Nanite scheme (Karis 2021, above) [OFFICIAL]; Arm ships a mobile Hierarchical-Z occlusion sample for tile-based GPUs (https://arm-software.github.io/opengl-es-sdk-for-android/occlusion_culling.html, acc.) [OFFICIAL]. Meta's Environment Depth (OpenXR `XR_META_environment_depth`) is per-eye, per-frame; the per-eye `EnvironmentDepthFrameDesc` exposes `createTime`, `predictedDisplayTime`, `createPoseLocation/Rotation`, FOV angles, `nearZ/farZ`, `minDepth/maxDepth` (https://developers.meta.com/horizon/documentation/unity/unity-depthapi-xr-oculus/, acc.) [OFFICIAL]; minimum effective range is ~0.2 m, static occlusion is fine but "cannot handle occlusion for objects that are dynamically moving" in the native doc's mesh-based variant, hand removal is optional, and "even if the application doesn't consume Environment Depth textures, a performance overhead still exists if the feature is enabled" (https://prod.developers.meta.com/horizon/documentation/native/android/mobile-depth/, acc.; https://developers.meta.com/horizon/documentation/unity/unity-depthapi-overview/, acc.) [OFFICIAL]. UploadVR reported at launch that resolution is "very low" and use is suggested out to ~4 m (https://www.uploadvr.com/quest-3-depth-api-mixed-reality-dynamic-occlusion/, Dec 2023) [COMMUNITY]. Horizon OS v83 (stable 24 Nov 2025) introduced "System Positional TimeWarp (SysPTW) from Depth-From-Stereo, real-time scene depth" (https://en.wikipedia.org/wiki/Meta_Horizon_OS_version_history, acc.) [COMMUNITY]. No paper or talk using headset depth sensors as HZB occluders for culling (as opposed to per-pixel occlusion) was found [UNVERIFIED gap].

Foveation: Quest FFR levels are 0-4 with the multiplier map published for Quest 3 (white = full, green = 1/4 resolution) (https://developers.meta.com/horizon/documentation/unity/os-fixed-foveated-rendering/, acc.) [OFFICIAL]. Quest 3 exposes `VK_EXT_fragment_density_map`, `VK_QCOM_fragment_density_map_offset` and `VK_KHR_fragment_shading_rate` (https://gist.github.com/tcoppex/6ef9f5f60ddae41d6198d2bdf4a40beb, Aug 2026) [COMMUNITY]. Zhang & Peng (Virtual Reality 30:82, 2026) fold eccentricity into LOD selection with a dual criterion (distance + eccentricity), a hierarchical patch structure for load estimation, and a fixed total-load constrained optimisation solved on the GPU; a 96 M-triangle scene rendered at 113 FPS (https://link.springer.com/article/10.1007/s10055-026-01316-3, 2026; conference version https://ieeexplore.ieee.org/document/10972961/) [PEER-REVIEWED]. CLOD already lowered point density toward the periphery in VR (2019, above).

**Implications for the contract**
- Occluder source = min(own previous-frame depth reprojected with the previous view-projection, Environment Depth reprojected using its own `createPose` and FOV), then HZB = max over texels. Apply an erosion/margin to the Environment Depth contribution and ignore it below 0.2 m and beyond ~4 m; treat missing/invalid depth as "far" (never an occluder).
- Two-pass: pass 1 tests against last frame's HZB with last frame's transforms and draws survivors; pass 2 rebuilds HZB from pass-1 depth (+ env depth) and tests only nodes rejected in pass 1. Readout budget must cover the second-pass survivors.
- Foveated error: scale τ by the FFR density zone (τ×2 in the 1/4-resolution zone at minimum) and, when using `VK_EXT_fragment_density_map`, derive the zone from the same density map so LOD and shading rate agree. Expose an eccentricity weight, as in Zhang & Peng, inside the fixed-budget selection.
- Temporal reuse: persist the cut and the pass-1 visible set across frames (Nanite/Atlas); re-evaluate only nodes whose error is within a band of τ or whose HZB test flipped.

## D. Adaptive spatial indexing for dense surfel maps

Nießner et al. (TOG 32(6), 2013) allocate 8^3 voxel blocks through a spatial hash with bucket lists and no hierarchy (https://niessnerlab.org/papers/2013/4hashing/niessner2013hashing.pdf, 2013) [PEER-REVIEWED]. MrHash (TOG, arXiv 26 Nov 2025) keeps a single flat hash whose entries store block coordinates, a collision offset, a GPU pointer and a resolution-level index; hash `H = (x·p1 ⊕ y·p2 ⊕ z·p3) mod n`; buckets of 10 with linked overflow of 7; each resolution level lives in its own GPU heap so access stays O(1); blocks start at the finest level and are merged where TSDF variance (Welford, incremental) stays under a user threshold; streaming to host is capacity-driven at 85 % GPU-memory utilisation. Result: up to 13x faster and 4x less memory than Nießner voxel hashing, 59 FPS multi-resolution on ScanNet (https://arxiv.org/html/2511.21459, Nov 2025; https://dl.acm.org/doi/10.1145/3777909) [PEER-REVIEWED]. Hive (arXiv Oct 2025) is a warp-cooperative GPU hash that resizes without global rehash by linear hashing in warp-parallel K-bucket batches, sustaining 95 % load and 1.5-2x the throughput of SlabHash/DyCuckoo/WarpCore (https://arxiv.org/abs/2510.15095, Oct 2025) [UNVERIFIED preprint]; SlabHash is the peer-reviewed baseline for on-demand growth via linked slabs (https://par.nsf.gov/servlets/purl/10062407, IPDPS 2018) [PEER-REVIEWED].

**Implications for the contract**
- Key = (block coords, level); per-level block heaps; bucket 8-10 with a short overflow chain. Level index in the entry lets the readout pick surfel density per block without a tree walk.
- Growth without stalls: incremental linear-hashing expansion in fixed-size bucket batches spread across frames, triggered by load factor (Hive), never a full rehash inside a frame.
- Split/merge driven by per-block variance (Welford) of surfel position/normal, with hysteresis; flower-shop foliage will sit at the finest level, walls/floor at coarse levels.
- Eviction policy: capacity-driven (85 %) and distance-ordered, not proximity heuristics.

## E. Information-driven measurement selection in RGB-D fusion

Fontán, Civera, Triebel (CVPR 2020) select points greedily by the increment of the pose information-matrix determinant; tracking 24 informative points per keyframe instead of 500 gives roughly 10x less computation with negligible accuracy loss (5-10x measured on an i7-7500U), and keyframes are created on an entropy-reduction criterion (https://openaccess.thecvf.com/content_CVPR_2020/papers/Fontan_Information-Driven_Direct_RGB-D_Odometry_CVPR_2020_paper.pdf, Jun 2020) [PEER-REVIEWED]. Geometric edges from range discontinuities and normal changes are the standard "keypixel" prior for RGB-D (https://people.csail.mit.edu/cchoi/pub/Choi13iros_edge.pdf, IROS 2013) [PEER-REVIEWED]. On the fusion side, StaticFusion admits new surfels with viability w -> 0 and only raises w through repeated observation (section F) [PEER-REVIEWED]. No paper was found that measures the *reconstruction* effect (accuracy/coverage vs. fused-pixel budget) of information-driven pixel subsetting at fusion time; the measured effects are for tracking [UNVERIFIED gap].

**Implications for the contract**
- Two budgets: a tracking pixel budget (tens to a few hundred informative pixels, Fontán) and a fusion budget prioritised by depth-edge/normal-change pixels plus low current surfel confidence (highest expected information for the map).
- Because the reconstruction-side gain is unmeasured, the contract should log coverage and mean surfel confidence per frame as acceptance metrics rather than assume a speed-up.

## F. Dynamic-scene gating in surfel/RGB-D SLAM

StaticFusion (ICRA 2018): K-means geometric clusters, each with a static score b in [0,1]; residuals above c = 0.5·r̄ (mean residual) push a cluster to dynamic; spatial (λR) and prior (λP) regularisers; weighted fusion; new surfels start with viability w -> 0; QVGA input, ~30 ms/frame on a GTX 1070 (https://ieeexplore.ieee.org/document/8460681/, 2018; PDF https://www.robots.ox.ac.uk/~mobile/Papers/2018ICRA_scona.pdf) [PEER-REVIEWED]. ReFusion (IROS 2019): residual histogram threshold with weight γ = 0.5, depth-aware flood fill with θ = 0.007 (m) and dilation, voxel 1 cm, truncation 0.1 m, colour weight 0.025; free-space rule "a voxel that was found to be reliably empty can never contain a static object" (https://arxiv.org/abs/1905.02082, May 2019) [PEER-REVIEWED]. MID-Fusion tracks static background and per-object volumes with Mask R-CNN preprocessing (https://arxiv.org/pdf/1812.07976, ICRA 2019) [PEER-REVIEWED]; Co-Fusion/MaskFusion segment by ICP motion or Mask-RCNN + geometric edges on top of ElasticFusion (summarised in https://arxiv.org/pdf/2505.12384, May 2025) [UNVERIFIED preprint]. Gaussian SLAM in 2025-26: Dy3DGS-SLAM fuses optical-flow and depth masks in a probabilistic model and drops dynamic pixels from the rendering loss (https://arxiv.org/abs/2506.05965, Jun 2025) [UNVERIFIED preprint]; GARAD-SLAM (ICRA 2025, https://arxiv.org/pdf/2502.03228) [PEER-REVIEWED]; RGD-SLAM (Pattern Recognition, Jan 2026, https://www.sciencedirect.com/science/article/abs/pii/S0031320326000348) [PEER-REVIEWED]; DL-SLAM uses dual-level (pixel + Gaussian) probabilities (https://arxiv.org/pdf/2607.01860, Jul 2026) [UNVERIFIED preprint].

**Implications for the contract**
- Working thresholds to adopt as defaults: residual gate at 0.5·mean residual (StaticFusion) or γ = 0.5 on the residual histogram (ReFusion); flood-fill depth continuity 7 mm; free-space violation as a hard veto; surfel viability counter before a surfel becomes "stable".
- Moving leaves are sub-cluster motion: cluster-level scores are too coarse, so add a per-surfel temporal-variance gate (position/normal variance over the last N observations) that lowers confidence instead of deleting, and a free-space-carving rule to remove leaves that swung away.
- Do not depend on semantic masks (no plant/person classes will be reliable in a flower shop); residual + free space are class-agnostic (ReFusion's argument).

## G. Transparent, specular and glass surfaces

Commercial RGB-D sensors fail on transparent/specular surfaces because projected light passes through or scatters (https://link.springer.com/chapter/10.1007/978-981-16-2336-3_53, 2021) [PEER-REVIEWED]. Curto & Araujo (Sensors 2022) measured D415/SR305/L515 on transparent and translucent scenes; D415 (active stereo) had the best precision and valid-measurement rate (https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9572012/, 2022) [PEER-REVIEWED]; a "<55 % valid pixels on clear glass" figure circulates for RealSense but was not traced to a primary source [UNVERIFIED]. Polarisation structured light is a hardware-level fix (https://www.nature.com/articles/s41467-023-42678-5, 2023) [PEER-REVIEWED]. Meta's Depth API documentation states only the 0.2 m minimum range and gives no glass/mirror behaviour [OFFICIAL, gap]; Quest 3 depth is stereo-derived ("Depth-From-Stereo", v83 notes above) [COMMUNITY]; community guides report reflective surfaces confusing tracking/passthrough (https://euphoriaxr.com/how-to-make-the-meta-quest-3-camera-better/, acc.) [COMMUNITY]. No measurement of Quest 3 depth on cellophane was found [UNVERIFIED gap].

**Implications for the contract**
- Gate by evidence, not material: per-pixel/per-surfel confidence from (i) temporal depth variance, (ii) left/right or depth-vs-PCA-stereo consistency, (iii) local valid-pixel ratio. Surfaces failing the gate become appearance-only surfels (colour, no geometric weight) attached to the nearest confident geometry behind or in front.
- Glass planes: allow a "see-through" flag on nodes so the HZB never uses appearance-only surfels as occluders.
- Require a cellophane/glass test scene in acceptance tests; record valid-depth ratio and temporal variance as the measured, reportable outcome.

- **Versioning.** v85 (PTC 7 Jan 2026, stable 26 Jan 2026) was the last "vNN" release; Meta restarted numbering as Horizon OS 2 with v2.1 (PTC 9 Feb, stable 23 Feb 2026), followed by 2.3-2.5 and v2.7 on 26 Aug 2026 (https://en.wikipedia.org/wiki/Meta_Horizon_OS_version_history, acc.; https://truenorthvr.com/meta-quest-v2-1-update-overview/, Feb 2026) [COMMUNITY]. "v86-v90" therefore do not exist; SDK package numbering should be checked separately (https://developers.meta.com/horizon/documentation/unity/release-archive/, acc.) [OFFICIAL].
- **Passthrough Camera API.** Camera2 access from v74; public release v76 (Apr 2025); Unity doc lists 320x240/640x480/800x600/1280x960 from v81 and 640x360/720x480/720x576/1024x576/1280x720/1280x1080/1280x1280 from v83; default max 60 FPS; permission `horizonos.permission.HEADSET_CAMERA`; intrinsics = FocalLength, PrincipalPoint, SensorResolution, LensOffset; unsupported resolutions fall back to the closest lower one (https://developers.meta.com/horizon/documentation/unity/unity-pca-documentation/, acc.; https://developers.meta.com/horizon/blog/new-era-mixed-reality-passthrough-camera-api-machine-learning-computer-vision/, 2025) [OFFICIAL]. At the experimental launch UploadVR reported 1280x960 at 30 FPS with 40-60 ms latency (https://www.uploadvr.com/quest-passthrough-camera-api-experimental-out-now/, Mar 2025) [COMMUNITY]. No official statement on left/right frame synchronisation, exposure/ISO metadata or a distortion model was found in the Unity or Android docs [UNVERIFIED gap]; the Unity OpenXR Meta 2.2 package explicitly "does not support AR Foundation image capture" (https://docs.unity3d.com/Packages/com.unity.xr.meta-openxr@2.2/manual/features/camera.html, acc.) [OFFICIAL].
- **Depth / scene.** v83 (stable 24 Nov 2025): SysPTW from depth-from-stereo and Space Setup support for multi-height floors, slanted ceilings, inner walls (Wikipedia version history, above) [COMMUNITY]; High-Fidelity Room mesh requires OS v83+/SDK v83+ (https://developers.meta.com/horizon/documentation/unity/unity-scene-roommesh/, acc.) [OFFICIAL]; Environment Raycasting API arrived in v81 (https://developers.meta.com/horizon/blog/q4-developer-recap-whats-new-across-meta-horizon-os/, 4 Dec 2025) [OFFICIAL]. No new spatial-scanning or mesh API was found in OS 2.1-2.7 [UNVERIFIED gap].
- **Unity.** Oculus XR Plugin deprecated in favour of Unity OpenXR (Unity 6 + Meta XR SDK v74+), with Unity OpenXR: Meta 2.1 at parity from OpenXR 1.14 (https://docs.unity3d.com/6000.3/Documentation/Manual/com.unity.xr.meta-openxr.html, acc.) [OFFICIAL]. From Unity 6000.3, URP has native Vulkan subpasses via RenderGraph, so Meta's custom URP subpass forks (2022.3/staging-subpass, 6000.0/17.0.3-subpass, 6000.0/17.0.4-subpass) are no longer needed (https://developers.meta.com/horizon/documentation/unity/vulkan-subpasses/, updated 16 Jun 2026) [OFFICIAL].

Meta's RenderDoc fork (29 Jul 2026) fixed an "Adreno timing hang" (https://developers.meta.com/horizon/release-notes/, acc.) [OFFICIAL].

**Implications for the contract**
- Rename all "v86-v90" references to Horizon OS 2.x and gate features on OS 2.1+ / SDK v83+ as appropriate.
- Camera path: request 1280x1280 or 1280x960 at 60 FPS, but treat stereo synchronisation and exposure metadata as unverified; the contract must include a runtime check of per-eye timestamp deltas and a fallback to single-camera + Environment Depth.
- GPU timing: without calibrated timestamps, the readout must use `vkCmdWriteTimestamp` deltas only (relative GPU time) and correlate to CPU time by frame fences; do not specify a cross-clock alignment.
- Pipeline cache: `VK_KHR_pipeline_binary` is available; the contract may require warm-start of the culling/compaction pipelines from stored binaries.
- Unity 6000.3+: rely on RenderGraph-native subpasses for the depth-prepass -> HZB -> surfel pass chain; drop the Meta URP forks.
